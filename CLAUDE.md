# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

voxanet is a single-binary Rust voxel engine that renders an explorable spherical planet with wgpu (30) / winit (0.30), glyphon for text, glam for math. There is no library crate and no CI config.

**Source layout** (`src/main.rs` plus domain folders, each a module with a `mod.rs`): `app/` (console `cmd.rs`, screenshots, perf log, diagnostics), `player/` (controller, entity/health, physics, landing and glide, smoothing), `planet/` (`data.rs` = `PlanetData`, noise terrain, biomes, materials, hex geometry), `meshing/` (chunk/LOD mesh generation `gen.rs`, low-poly, bevels, Marching Cubes tables, LOD fades), `render/` (renderer, deferred passes, shadows/AO/ray tracing, atmosphere, clouds, env map, plastic, film, lens flares, and their WGSL), `weather/` (weather map, precipitation), `space/` (the solar system and its space-mode rendering: `solar_system.rs` = `SolarSystem`, planets, orbits, `SpaceFlight`; `render.rs` = `SpaceRenderer`; `impostor.rs` = far/near planet impostors; `map.rs` = the solar-system map and galaxy view (`MapView`, `MapCamera`, picking); `travel.rs` = trips to a planet's orbit; `galaxy.rs` = the galaxy catalogue `Galaxy`; `universe.rs` = `Universe`, the current and parked solar systems; `space.wgsl`; `icosphere.rs`; `star_shading.rs`). What used to be called "galaxy" is one solar system (a star and its planets), so the code says `SolarSystem`, `Planet`, `SpaceFlight` and `/system`; "galaxy" now means the catalogue of 300 solar systems (`Galaxy`, the galaxy view, `/galaxy`, `/jump`).

```sh
cargo run --release   # debug builds are very slow for terrain/mesh generation
cargo build
cargo check
cargo clippy
cargo test            # ~360 unit tests, inline #[cfg(test)] modules in src/planet/biome.rs, src/app/cmd.rs, src/planet/data.rs, src/player/entity.rs, src/meshing/gen.rs, src/planet/hex.rs, src/meshing/lowpoly.rs, src/meshing/mc_tables.rs, src/planet/material.rs (and others); `cargo test --release lowpoly_bench -- --ignored --nocapture` is the low-poly meshing benchmark
```

One-time per clone: `git config core.hooksPath .githooks` enables the pre-commit hook (`.githooks/pre-commit`), which `rustfmt`s staged `.rs` files and re-stages them, then runs `cargo clippy` as advisory output (printed, never blocks the commit — the tree has pre-existing warnings and clippy's suggestions aren't always safe to apply blindly). Line endings are LF-normalized via `.gitattributes`; `rustfmt.toml` just pins `edition = "2021"` so standalone `rustfmt` (not `cargo fmt`) picks it up. Nothing here has been run across the whole codebase yet — `cargo fmt` on every file would be a ~10,900-line diff against the existing hand-tuned dense style (very long single-line struct/pipeline literals throughout), so formatting is applied incrementally, only to files a commit actually touches.

## Architecture

### Data model: heightmap + sparse edit diffs
The planet is not stored as a voxel array. `PlanetData` (`src/planet/data.rs`) holds:
- `terrain: PlanetTerrain` (`src/planet/noise.rs`): a precomputed per-column height map indexed by `(face, u, v)`, generated once per resolution (in parallel with rayon). `TerrainShape` builds it from continent noise (ocean vs land around a sea level at layer `res/2`), hills, and ridged mountain noise inside low-frequency mountain zones; overall relief scales with `3·sqrt(res/2)`, capped at 20% of the radius (layers stay ~1 unit thick, so small planets need proportionally less relief). Seeded: `PlanetTerrain::new(resolution, seed)`; `PlanetData::seed` records the seed it was baked with (the planet's `noise_seed`; `noise::HOME_SEED` = 42 is only the default for `PlanetData::new`, used by tests). **Per planet type** (spec `docs/superpowers/specs/2026-10-11-terrain-profiles-design.md`): `TerrainShape` stores the `PlanetType` (`PlanetTerrain::for_type`, from `PlanetData::new_for_type`; the impostors pass it too, so orbit and ground match) and `natural_height` dispatches to one profile per type, all sharing the continent mask `continent()` = fbm + `land_offset(type)` (Earth-like and most types 0.08, Desert 0.5, Ocean −0.25) and the relief R; every new profile goes through `soft_cap` (unchanged below 0.8R, never above 1.2R). Earth-like is today's formula bit for bit (`earth_like`, pinned by the fingerprint tests). Volcanic: ridges on all land, calderas (cellular cells of 60 units, half of them, a rim around a bowl below sea level, so lava fills it), fissures (the band around the zero crossings of one noise octave, period 40 units, so at least 2 columns wide). Per-cell features (caldera, crater, spike) fade by `smoothstep(0, 0.1, f2 − f1)` so they have no cliffs at cell boundaries. Ice: smoothed billow hills, the frozen seas (the sea-level fill), rare ice spikes (cells of 40 units, 15 %, a 10-column-radius cone). Desert: ridged noise terraced in steps of max(2, R/8) layers (mesas), canyons cut down to sea level + 1 (never into the fill), low dunes. Toxic: flat land with a crater per cell (30 units), floors below sea level (sludge fills them). Ocean: deep floor, steep islands where the mask breaks through (≈ 4 % land). Shattered: each Voronoi cell (50 units) a plate at its hashed height, cracks below sea level where the two nearest cells are about equally near (plasma fills them, as it does sunken plates), shard ridges. Cratered (lunar, airless, no liquid): `cratered()` = highlands (`0.30R` + 4-octave fbm × `0.10R`) with `mare_mask` (`1 − smoothstep(MARE_LO −0.09, MARE_HI 0.04, continent)`, about 30 % of the surface, tested to 22–38 %) flooding the low continent-mask areas flat, plus three `crater_layer`s (`CraterLayer::Large/Medium/Small`, cells of 150/55/20 world units, bowl depth 0.16/0.12/0.10 R, rim height 0.025/0.030/0.030 R, rim width 0.10/0.07/0.05; half of the cells hold a crater of radius 0.25–0.45 of the cell, a smooth bowl plus a raised rim, faded by `smoothstep(0, 0.1, f2 − f1)` so no cliffs): on the maria only the small fresh craters survive, at a quarter of their strength, large and medium ones only on the highlands. The result goes through `softplus_above` onto `MIN_FLOOR` (1 layer above sea level: liquid-less planets are filled flat to sea level, so a deeper floor would be a plateau, and the maria sit exactly on it) and `soft_cap`. Noise building blocks in `NoiseGenerator`: `billow`, `cellular` (f1, f2 and the nearest cell's hash, 3×3×3 search, feature points jittered within 0.1–0.9 of their cell), and `terrace`. Cell sizes are in world units at sea level (`cells`: frequency radius / size), about columns near a face centre (a column averages π/4 units wide), so features keep their size on every planet. Bake time at res 500: Earth-like ~80 ms, the slowest profile (Toxic) ~1.3×; Cratered (three cellular layers) ~1.6× Toxic (0.21 s vs 0.13 s, `cratered_bake_time_is_at_most_twice_toxics`, ignored, budget 2×). Character tests per type in `src/planet/noise.rs`; low-poly smoothing bounds per type in `src/meshing/lowpoly.rs`.
- **Lakes** (liquid planet types only: `PlanetData::new_for_type` → `PlanetTerrain::with_lakes`; `PlanetTerrain::new` and `PlanetData::new`/`new_seeded` make none, so the home-seed fingerprint test stays bit-identical): `TerrainShape::new(resolution, &generator, with_lakes)` places up to `min(3 + R/50, 8)` lakes from 400 seeded candidates (centre ≥ 2 layers above sea, the whole edge ≥ sea + 2, no overlap, ≥ 30% of the region under water; radius `clamp(0.2·R, 6, 50)` × 0.7–1.0 blocks). Each `Lake` has a region warped ±35% by noise around its centre (`Lake::distance` < 1 inside), a `level` one layer below the lowest natural height along the region's edge (sampled about once per block, so the rim always holds the water), and lowers the terrain inside by a smooth falloff (`TerrainShape::sample`; a subtraction, so hills inside stay islands and the shoreline follows the terrain's contours). Small, low-relief planets get few or none. `PlanetTerrain` keeps a separate 1-byte `water_body` map (0 = sea, k + 1 = inside lake k's region, underwater or not) plus a level table: `water_level(face, u, v)` is the column's water layer (its lake's, else sea level). Shores and islands inside a region therefore measure their beach band from the lake (sand at any lake height), and a hole dug into them fills to the lake's level. It is separate from the heights so solidity checks, which read heights only, don't fetch it.
- `chunks: HashMap<ChunkKey, ChunkMods>`: only the player's edits per 32×32 column chunk (`CHUNK_SIZE`): `placed: HashMap<BlockId, BlockType>` and `mined: HashSet<BlockId>`.

`PlanetData::exists(id)` is the single source of truth for solidity: placed → true, mined → false, otherwise `layer <= height`. Meshing, physics, and raycasting all go through it. Edit limits: `add_block` refuses cells above `build_ceiling()` (the highest natural peak + `BUILD_MARGIN` 24 layers, but never into the cloud shell at `CLOUD_ALT` radii, a Rust copy of the WGSL constant checked by a test), `remove_block` refuses cells below `mining_floor()` (the lowest natural column − `BEDROCK_DEPTH` 32 layers, never into the 6-layer core; `material::natural_type` makes everything below it Bedrock), and both refuse new entries beyond `MAX_EDITS` (1,000,000; undoing edits always works). They return `Result<(), EditRefused>`; `src/main.rs` also refuses placing into the player's body (`Physics::overlaps_block`, the same sample points as `check_collision`) and shows each refusal in the HUD status line. The edits are one value, `PlanetData::edits: PlanetEdits`: the `ChunkMods` map behind an `Arc` (copy-on-write via `Arc::make_mut`, so cloning a `PlanetData` shares the edits instead of copying them), the entry count, and the terrain they were made on (`resolution`, `noise_seed`). `take_edits` hands them over and `restore_edits` puts them back, refusing edits from another terrain; `edit_generation()` counts successful edits (restoring isn't one). `PlanetData::surface(face, u, v)` is a column's top solid layer after edits (the natural `effective_height` in unedited chunks, without scanning; else searched down from the build ceiling): `MeshGen::generate_lod_mesh` samples it for positions and the top block's colour, so large builds and pits show in the LOD terrain and the near impostor (point sampling, like natural terrain; thin towers can come and go between LOD levels). Edits are kept per planet for the session only (no save file yet; `PlanetEdits` is shaped to be serialised later).

**Smooth heights** (`PlanetData::smooth`, `bake_smooth`; in `PlanetData`, not `PlanetTerrain`): per column the mean effective height of itself and its up to eight neighbours (`CoordSystem::neighbour_columns` / `PlanetData::neighbour_columns`: diagonals across a cube-face edge stepped from the in-face neighbour, seven at a cube corner), baked with the planet; `smooth_height`, `smooth_corner` (grid corners). The low-poly terrain is drawn on it; blocks stay the truth (`exists`, physics, raycast, edits), so the drawn surface over a column differs from its top block by `|smooth − h|`: on the start planet typically ≤ 0.56 layers (99th percentile; mean 0.16), at most 1.78 layers on crests and valleys, over 1 layer on 0.01 % of columns (`start_planet_smooth_surface_stays_near_the_blocks`, ignored; `smooth_surface_stays_near_the_blocks` for a res-64 planet: max 1.67).

Block types live in `src/planet/material.rs`. Natural blocks have no stored type: `material::natural_type` derives it from the column's height within the planet's height range (`PlanetTerrain::height_range`), the slope to neighbouring columns and smooth per-column jitter (sand on beaches and the sea floor, stone on steep steps and from 45% of the peak height above sea level, snow from 62%, dirt then stone below the surface). `PlanetData::block_type(id)` combines that with edits; voxel and LOD meshes both use it, so they agree.

### Frame structure: deferred shading (`src/render/deferred.rs`)
`Renderer::render` draws the scene geometry once per frame:
0. **Space backdrop** (`SpaceRenderer::render`, submitted on its own before the frame's encoder): the stars (and on a planet the star and the other planets) behind everything, from the planet camera's pose; it uses `Deferred::depth`, which the geometry pass clears again. See "Atmosphere and clouds".
1. **Geometry pass** (`fs_geom`, full screen resolution): vertex colour (`Rgba8Unorm`), normal (`Rgb10a2Unorm`, `n * 0.5 + 0.5`), camera distance (`R32Float`, 0 = sky), the plastic's roughness (`gloss`, `R8Unorm`, see Plastic shading) and depth. Chunks, LOD meshes, fading chunks and the third-person player are drawn here; fading chunks dither (discard) as before.
2. **Shadows** (below): `cs_gbuf_down` derives the shadow-resolution G-buffer from it, then one compute invocation per shadow texel, then the blur.
3. **Lighting pass** (`vs_full` + `fs_light`): one full-screen triangle; `shade()` in `src/render/shader.wgsl` (lighting, fog, ACES, P3 output) runs once per pixel. Sky pixels (and distant terrain under cloud cover) get `sky_gradient()` + `clouds()` instead of a discard. The lighting pass **loads** the swapchain (the backdrop) instead of clearing it, and `fs_light` outputs premultiplied colour with the sky's opacity as alpha (`PREMULTIPLIED_ALPHA_BLENDING`): terrain is opaque, the sky only where the atmosphere is thick and sunlit. Radial motion blur (fast movement, `global.motion.x`) splits this step while it is on: `fs_shade` shades each pixel once into `Deferred::shaded` (`Rgba16Float`, premultiplied, before `post_process`), then `fs_motion_blur` averages taps of that image and post-processes once (`Deferred::shade_pipeline`/`blur_pipeline`). Re-shading every tap in place, as `fs_light` once did, cost ~120 ms a frame at 4K.
4. **Water** (`fs_water`, same pass, alpha-blended, depth-tested, no depth write): the per-chunk `ChunkMesh::water` meshes (`MeshGen::build_water`: one quad at the top of each column's `water_level` over every column that holds water and whose cell above is open). Water is a water table: `PlanetData::holds_water` — the planet has a liquid and the cell at the column's `water_level` (its lake's level, else sea level) is empty (`!exists`) — so natural ocean, lakes, and holes dug below their column's level alike hold water, whether or not they connect (no flow: a hole dug beside a lake, outside its region, fills only to sea level, and a channel dug out of a lake stays dry, showing a wall of water at the lake's edge; flowing water was deferred; there is no water block type, water is derived, never stored). `water_surface_radius(face, u, v)` is that surface's radius, 0 when dry. A tunnel dug at sea level under a ceiling holds water but gets no surface (it would flicker against the face above). Swimming (`water_depth`) and the F-landing lava check (`landing::over_damaging_liquid`) use the same rule, see Gameplay loop. Opacity and colour (turquoise → deep blue) come from the water depth along the view ray, using the G-buffer distance of the sea floor behind the surface. The mesh stays flat: ripples only tilt the shading normal (`water_waves`: six travelling sine waves along fixed world directions, so no seams at cube faces, each fading out with distance before it aliases), and shore foam comes from the vertical water depth (`FOAM_DEPTH`; a surf line plus bands running toward the shore). Time is `GlobalUniform.screen.w` (seconds, wrapped at 3600). Caustics are in `shade()` (so in `fs_light`; `fs_main` passes no depth): sunlit surfaces below a water surface get their direct sunlight scaled by `caustics()`, the light density `1/|1 + depth·curvature·CAUSTIC_FOCUS|` of six ripples (`ripple_curvature`, 0.8–1.9 blocks, separate from the surface waves; directions spread evenly over a hemisphere, curvature measured within the local sea surface, lookup point warped by a slow large-scale distortion against visible tiling) at the point where the sun ray entered the water. The depth comes per pixel through the G-buffer: `Vertex::water` (the water surface radius over the cell a face looks into — its own column for top/bottom faces, the neighbour for side faces — 0 when that column holds no water; `Vertex::ATTRIBUTES` location 3 in the four scene pipelines) and `fs_geom` writes the depth below it into the albedo alpha (`/ WATER_DEPTH_RANGE` = 16 layers); `fs_light` passes `albedo.a × 16` to `shade()`. So lake floors get caustics and tunnels sealed off from water don't. Keep the wave sums unrolled with constant unit directions: a loop over constant arrays was ~3× as expensive. Distant oceans are part of the LOD meshes instead (clamped to sea level, `material::WATER_COLOR`, opaque). `GlobalUniform.screen.z` is the water surface radius over the camera's own column (`Renderer::camera_water_radius`: its lake's or the sea's, 0 when that column holds no water; also the flare's under-water check), `screen.w` the animation time; `fog()` tints everything when the camera is below it. Chunk bounds include the water vertices. Water's sky-direction fresnel reflection also calls `clouds()`, so cloud shapes show up reflected on the surface. Seen from above the cloud shell, `fs_water` composites the clouds in front of the surface like `shade_pixel` does over terrain ("clouds over water" with the water's own alpha: the floor behind already has the clouds over it, so the blend is exact before post-processing); without it liquids were drawn on top of the clouds, sharp fragments of plasma or water floating in the cloud cover. On a curved planet a grazing view ray can pass under the water without reaching the sea floor (G-buffer distance 0 behind the surface) and come up through the surface again further on; `fs_water` therefore discards surfaces seen from below while the camera is above the sea (they'd otherwise cover the near surface depending on chunk draw order: holes into space), draws the surface opaque where nothing is behind it, and folds reflection rays that ripples tilt below the horizon back above it (the sky/cloud lookups of a downward ray return space and the far side's clouds).

### Atmosphere and clouds (`src/render/shader.wgsl`, no geometry)
The atmosphere maths lives in `src/render/atmosphere.wgsl` (sky gradient, limb, sky opacity, clouds, cloud shadow, air fog, ACES/gamma), parameterised by an `Atmosphere` (planet radius and colours) and prepended to both `src/render/shader.wgsl` (src/render/renderer.rs `SCENE_SHADER`) and `src/space/space.wgsl` (src/space/render.rs `SPACE_SHADER`); the engine's `sky_gradient`/`clouds`/`cloud_shadow`/`fog`/`post_process` are thin wrappers feeding it the globals. Both combined shaders are validated with naga in `cargo test` (`scene_shader_is_valid_wgsl`, `space_shader_is_valid_wgsl`). Air fog counts only the stretch of the view ray inside the atmosphere (`atmo_fog_distance`, sphere at the limb scale): unchanged on the ground, but from orbit the empty space in between adds no haze, so planets don't wash out into flat sky-coloured discs from a few radii out. Its colour is the sky dome without the sun disc (`atmo_sky_dome` × opacity): a fogged ray ends at terrain, which hides the sun, so terrain in front of the sun (a sunset horizon, the night side from orbit) doesn't fade toward the disc; the dome's sun glow still brightens haze toward the sun. `atmo_sky_gradient` = `atmo_sky_dome` + `atmo_sun_disc`; `atmo_sun_disc` draws the solar system's star at its real angular radius from the installed planet (`Atmosphere.star_angle`, `Planet::star_angular_radius`) with `src/render/star.wgsl`'s surface and corona (the star's look travels in `Atmosphere.star`, filled from `BiomeUniform`'s star fields), so the sky's sun matches the solar system star at the handover; the impostors' atmosphere shell passes `star_angle` 0 (dome only), since the solar system draws the star itself. A thin cloud shell at `CLOUD_ALT × planet radius` and a stylised sky gradient are drawn without extra geometry: `sphere_hit()` finds where a ray crosses the shell, `cloud_shade()` (`atmo_cloud_shade` in `src/render/clouds.wgsl`) raymarches a short span around that point (scaled by `1 / |ray·up|`, so grazing/horizon rays cross far more of the shell and look thicker, same as real atmosphere), and `sky_gradient()` gives a blue-dome-to-black-space falloff plus a limb glow when the planet is viewed from outside its atmosphere. Three call sites share this: `fs_light`'s sky branch, `fog()` (so horizon fog matches the sky in that direction instead of a flat colour), and `fs_water`'s reflection. `cloud_shadow()` (one cheap unwarped noise sample, no raymarch) dims direct sunlight under cloud cover in both `shade()` and `fs_water`. Cloud/sky shape noise is in direction-space (`fbm_clouds`, a domain-warped value-noise FBM, same no-seams reasoning as `ripple_curvature`), not world-position space. It is not evaluated per pixel: **the cloud map** (`src/render/cloud_map.rs`, `src/render/cloud_bake.wgsl`) bakes it into a 512² `R16Float` cube-map array of 3 snapshots `SNAPSHOT_SECS` (0.5 s) apart — the two around the current time, blended by `CloudMapParams`, and the next, baked ahead one cube face per frame plus its mip chain (`Schedule`; a missing blended snapshot, at start-up or when the hourly clock wraps, is baked whole) — and `src/render/clouds.wgsl` (prepended after src/render/atmosphere.wgsl to the scene and space shaders; group 0 bindings 8–10 in both, `CloudMap::layout_entries`/`bind_entries`) samples the raw noise and thresholds it after filtering. The mip level comes from the pixel's footprint on the shell (`GlobalUniform.motion.y` / `SpaceCameraUniform.pixel.x`: radians per pixel, × distance), explicit because the cloud code runs in non-uniform control flow. Every planet shares the field, so one map serves the engine and all impostors and they match at the landing handover. At 4K this took the lighting pass from ~10–14 ms to ~5 ms; `cloud_shadow` still evaluates its own one-octave noise. The noise is direction-only, so it doesn't depend on the player's distance from the planet centre — which is why these functions read `global.camera_pos.w` (set to `planet.resolution / 2` every frame in `Renderer::render`) rather than `rt.resolution`: the latter is zeroed when hardware ray tracing is active (`RtParams::zeroed()` in the hw-shadows branch), since the ray-march windows aren't built in that mode. The sky is also **partly transparent** over the space backdrop (milestone 2 of the landing): `Renderer::render` first draws the solar system behind the voxel world (`render::Backdrop`: the starfield, the star and every other planet, from the planet camera's exact pose, `Controller::camera_pose`/`fov_y`, converted into space), and `fs_light` is alpha-blended over it (`Deferred::light_pipeline`, lighting pass loads instead of clearing). `sky_opacity()` = `smoothstep(SKY_SPACE_LIMB, SKY_OPAQUE_LIMB, atmosphere_limb())` × daylight at the ray's closest point to the planet (`smoothstep(SKY_NIGHT_ELEVATION, SKY_DAY_ELEVATION, sun elevation)`). `atmosphere_limb()` is the atmosphere-thickness term `sky_gradient` already used, but it is only ~0.7–0.9 for a camera standing on terrain, so it goes through the smoothstep rather than being the opacity directly (otherwise stars show through the daytime sky): fully opaque up to ~0.3 planet radii of altitude, fully transparent from ~1.1. `shade_pixel` carries premultiplied colour + coverage through cloud compositing and motion blur, and `fs_light` applies `post_process` to the premultiplied colour and blends with `PREMULTIPLIED_ALPHA_BLENDING`, so a sky pixel lands as `post(sky × a) + backdrop × (1 − a)` — the same `post(sky × a)` that `fog()` fades distant terrain toward (un-premultiplying first made fogged terrain brighter than the sky beside it in the semi-transparent band). Clouds dim to `CLOUD_NIGHT_BRIGHTNESS` on the night side (`cloud_shade`), otherwise they'd glow grey against the black night sky. `fog()` and `fs_water`'s reflection use `sky_over_black()` (sky × opacity), so at night they fade toward dark like the sky instead of toward blue. The engine's own sun disc fades with the opacity, so above the atmosphere the solar system's star is what's seen. Night skies are therefore dark and starry, with the solar system's star and other planets in them. Terrain darkens with them: `atmo_ambient_daylight()` scales the sky's fill light (`shade()`'s ambient, ground bounce and rim; the water pass's sky fill on water and foam; `fs_planet`'s ambient and rim on impostors) from white by day to `NIGHT_AMBIENT` (a dim, cool moonlight, ~12%) on the night side, over the same `SKY_NIGHT_ELEVATION`/`SKY_DAY_ELEVATION` band at the shaded point's own up, so the terminator runs across the terrain where the sky turns dark. Lava's emissive glow isn't scaled.

**Atmosphere density** (`AtmosphereDef.density`, 1.0 on the seven old types, 0.0 on Cratered; `Atmosphere.density` in `src/render/atmosphere.wgsl`, `BiomeUniform.atmosphere.x` / `PlanetUniform.atmosphere.x` / `FlareUniform.atmosphere.x`; the engine passes 1 in space mode): a scalar every use of which is a multiply or an early return (never a division, so 0 can't produce NaN; a test checks the sources). It scales `atmo_sky_opacity` (`thick * day * density`, so no sky: stars, star and planets show through in daylight, and `sky_over_black` and the fog colour vanish with it), the air fog (`atmo_air_fog`'s `fog_factor * a.density`, so distant terrain stays crisp), `atmo_cloud_shade` (early return of zero when `density <= 0`; its storm term and coverage alpha × density), the cloud shadows (`atmo_cloud_shadow`, `atmo_cloud_shadow_map`: `1 − density · coverage · …`), the storm fill drop (`STORM_FILL_DROP · storm · density` in `shade()` and `fs_planet`), the storm over the camera (`Renderer::storm_here`/`overcast` × density, so precipitation and the overcast dimming are off), the clouds drawn in front of impostor surfaces (`fs_planet`, skipped at density 0) and the env bake's sky (via sky opacity). The lens flare reads it through `FlareUniform.atmosphere` (its cloud-shadow term). Cratered's `sky_zenith`/`sky_horizon_warm` are not a sky but the dim cool fill light shadows get (about a quarter of Earth-like's). From orbit `space::render::has_atmosphere` skips the atmosphere shell for planets with density 0.

### Planet types (biomes) (`src/planet/biome.rs`, `src/planet/material.rs`, `src/render/renderer.rs`, `src/player/entity.rs`)
The planet type (Earth-like, Volcanic, Ice, Desert, Toxic, Ocean, Shattered or Cratered; each with its own landscape, see the data model's terrain paragraph) is stored in `PlanetData::planet_type` and set when a planet is baked (`Planet::bake` → `PlanetData::new_for_type`, which also decides lakes; `switch_planet_type` remains for tests only and keeps the terrain). Each `PlanetType` has a `PlanetTypeDef` (`src/planet/biome.rs`) defining its `Palette` (peak, rock, beach, ground, subsurface block types), optional `LiquidDef` (shallow/deep colour, behaviour, damaging flag), and `AtmosphereDef` (sky/cloud colours). `material::surface_type()` and `material::natural_type()` take the palette as a parameter, so material assignment depends on the active type. On liquid-less planets (Ice), `PlanetData::effective_height()` returns `height.max(sea_level)` instead of just `height`, making the terrain solid all the way up to sea level where there is no ocean mesh to draw; `exists()`, `natural_type()` and `src/render/rt_shadow.rs`'s `fill_face()` all call it, so solidity for meshing, physics, raycasting and shadowing agree. `BiomeUniform` (`src/render/renderer.rs`) captures the liquid and atmosphere colours from the active planet's `PlanetTypeDef`; it's recomputed and written fresh every frame in `Renderer::render` (`BiomeUniform::from_def()`), the same pattern `GlobalUniform` already uses — cheap, no change-tracking needed. `shade()` in `src/render/shader.wgsl` reads it for terrain lighting (sky gradient, clouds, ambient); `fs_water` reads it to colour the water (or lava on Volcanic) and adds emissive glow to glowing liquids (liquid_shallow.w = 1.0 for `LiquidBehavior::Glowing`). Cratered has no liquid and density 0 (see Atmosphere density): `BlockType::MoonDust` highlands (ground and peak), `Basalt` maria (beach) and subsurface, `Stone` crater walls, a 270 s day, no weather (`WeatherKind::None`). Liquid physics (`LiquidDef.physics`, `LiquidPhysics` in `src/planet/biome.rs`): `WATER` (Earth-like, Ocean) and `PLASMA` (Shattered, glowing but harmless) are swum in (`Player::swim`); `LAVA` (Volcanic) and `SLUDGE` (Toxic) are too thick: deeper than `SWIM_DEPTH` (0.5 blocks) the player wades on the bottom at `wade_speed` (lava 0.3, sludge 0.4), sinks no faster than `sink_speed` (`thick_liquid_vertical`) and jumps at `THICK_JUMP` (0.7: a one-block ledge, not out of a deep pit). The health system (`src/player/entity.rs`) damages the player at the liquid's `damage_rate` while submerged beyond `SWIM_DEPTH` (lava 20 HP/s, sludge 12 HP/s; `LiquidDef::damaging`), regenerates at `REGEN_RATE` (5 HP/s) otherwise; death respawns at the spawn point. Damaging liquids also refuse an F landing (the status line names the liquid, `LiquidDef.name`) and keep spawns off them. Spawns prefer dry land on every liquid planet (`safe_spawn_direction`: the dry sample nearest the wanted direction; required on damaging liquids). The HP readout (`HP: x/x`) is drawn in the top-right overlay, always visible (not gated on debug mode).
5. **Forward overlays** in the same pass, depth-tested against the G-buffer depth: collision lines, the translucent block cursor (`fs_cursor`, lit by `shade()`: a depth-only pre-pass, `pipeline_cursor_depth`, then a blended pass, `pipeline_cursor`, that keeps only its nearest surface), console; then text. There is no crosshair.

World positions are reconstructed from the camera distance and a camera ray basis (`GlobalUniform.ray_dirs`, built in f64 by `Renderer::ray_dirs` in homogeneous form so the per-pixel interpolation is exact). Don't use an f32 inverse view-projection for this: with near 0.1 / far 20000 it was off by ~0.5 units at 500 units, which made hardware rays self-shadow distant surfaces.

### Space mode (foundation) (`src/space/solar_system.rs`, `src/space/render.rs`, `src/space/icosphere.rs`)
A separate, deliberately minimal deep-space mode: a seeded single-star solar system of placeholder planets the player can free-fly through, entirely disconnected from the planet-surface engine above. `SolarSystem::generate(seed)` (`src/space/solar_system.rs`) builds a fixed `Star` plus `PLANET_COUNT` (8) `Planet`s with no true randomness anywhere — `orbit_for(seed, index)` gives each orbit from seeded hashes (`seeded_unit`, one salt per property): a radius ×`ORBIT_JITTER_MIN`..`ORBIT_JITTER_MAX` (0.95–1.10) around the geometric spacing (`INNER_ORBIT_RADIUS` 32,000 × `ORBIT_RADIUS_GROWTH`^i; neighbours keep a gap of at least ×1.29, the innermost stays at `INNER_ORBIT_RADIUS` or more, outside every star's heat zone), a random starting angle, and a small tilt (`orbit_tilt` up to `MAX_ORBIT_TILT` 4°, about the in-plane axis `orbit_node`); `orbit_speed` follows Kepler's third law (`orbit_speed_for`: period ∝ radius^1.5, `INNER_ORBIT_PERIOD_SECS` 180 s at `INNER_ORBIT_RADIUS`, so the outermost generated planet takes ~2 hours), and `planet_radius_for` derives a size in `[MIN_PLANET_RADIUS, MAX_PLANET_RADIUS]` (160–1000) from a bit-mixing hash of `(seed, index)` — so a given seed always reproduces the same system (see the `generate_is_deterministic_for_a_fixed_seed` / `generate_is_different_for_a_different_seed` tests). `Planet::position_at(t)` places each planet on its circle at a given time `t` (the XZ circle tilted by `orbit_tilt`; the planet's spin axis stays +Y, so on a tilted orbit the sun's height swings by ±tilt over the year — small seasons — and the solar day is exact only for untilted orbits); each cycles through `PlanetType::ALL` (`src/planet/biome.rs`; eight planets, eight types, so the start system has every type once and Cratered is #8; the generator then adds moons, below), so planet colour reuses the same per-type palette as the main planet-surface engine (`palette.ground.color()`) rather than inventing a second colour table. `SpaceFlight` (also `src/space/solar_system.rs`) is a separate, simpler kinematic body from `Physics`/`Player`: no gravity, no collision, no terrain-following floor, just mouse-look (`rotation`) and eased-toward-target-velocity flight (`compose_fly_direction`, `smoothing::ease_toward` with `FLIGHT_EASE_SECONDS` = 0.25 s, the same easing planet fly mode uses, so pressing and releasing keys ramps speed instead of switching it) at `SPACE_CRUISE_SPEED`/`SPACE_BOOST_SPEED`.
**Varied systems and planet traits** (spec `docs/superpowers/specs/2026-10-12-system-variety-design.md`): `SolarSystem::generate(seed)` (fixed 8 planets cycling through the 8 types, Cratered included) is the start system only; every other system is `SolarSystem::generate_varied(seed)` (`src/space/variety.rs`; `Universe::switch` uses it for every entry but 0, so `--seed n` still gives entry 0 exactly what it always gave, and the start planet's `PlanetTraits` are `NEUTRAL`). Orbits and radii come from `orbit_for`/`planet_radius_for` as before; the rest is seeded through `seeded_unit` with one salt per property (`SALT_COUNT_A/B` 20/21, `SALT_TYPE` 10, `SALT_DAY` 11, `SALT_RELIEF` 12, `SALT_LAND` 13, `SALT_HUE` 14, `SALT_STORM` 15, `SALT_DENSITY` 16; `orbit_for` uses 1-4). **Count:** `planet_count` = 3 + a + b, a in 0..=3, b in 0..=4 (3-10, 6-7 most common). **Type:** the temperature index `tau = log2(r / (108,000 * sqrt(luminosity)))` (`temperature_index`, `habitable_orbit`; `StarTypeDef.luminosity` per star type; 0 at the habitable distance, negative hot, positive cold) feeds `type_weights(tau)`: Volcanic 1 up to tau -1.6 then a bump, Desert bump(-0.8, 0.5), Toxic 0.8 * bump(-0.6, 0.6), Earth-like bump(0, 0.35), Ocean 0.9 * bump(0.3, 0.45), Ice a bump to 1.4 then 1, Shattered a flat 0.08, Cratered 0.12 + 0.25 * bump(1.8, 0.8); `pick_type` is a seeded weighted pick, so hot orbits get Volcanic/Desert, the middle Earth-like/Ocean, the cold Ice. **Traits** (`traits_for`, `PlanetTraits` in `src/planet/traits.rs`, a field of `Planet` copied into `PlanetData::traits` at bake time; `NEUTRAL` = all 1/0 and reproduces the type bit for bit, the pinned fingerprint tests rely on it): `day_scale` 0.6-1.6, `relief` 0.7-1.4, `land_shift` -0.15..+0.15 (0 without a liquid), `sky_hue` -0.25..+0.25 rad, `storminess` 0.5-1.5, `gravity` = `gravity_for_radius(radius)` (piecewise linear: radius 40 → 0.15, 160 → 0.6, 1000 → 1.3; planets are 160–1000) × (0.9 + 0.2 * density jitter), so about 0.54-1.43. Consumers: `Planet::day_length` = the type's `day_length_secs` * `day_scale` (spin and solar day follow it); `TerrainTweaks { relief, land_shift }` (`PlanetTraits::terrain`) scale the relief R and add to `land_offset` in `TerrainShape::tweaked`, via `PlanetTerrain::for_planet` / `PlanetData::new_for_planet` (the bake; the impostors pass the same tweaks, so orbit and ground match); `PlanetTraits::tinted_def(type)` = `type.def()` with `AtmosphereDef::tinted(sky_hue)` (hue rotation of sky and cloud colours), the one source of a tinted atmosphere for the engine (`Renderer::render`), the impostors' `PlanetUniform`, LOD water and impostor water; `WeatherSettings::set_storminess` (true when it changed, then `weather_changed` rebakes the maps) sets `WeatherForce.shape.x` = `weather::storm_shift(storminess)` = `STORM_SHIFT` (0.12) * (1 - storminess), a shift of the storm thresholds in `weather.wgsl` (stormier = lower), applied by `Renderer::apply_storminess` (every frame's planet state and `install_world`); the weather and cloud maps are shared by all planets, so other planets in the sky show the installed planet's storminess; fog and lightning inherit the shift because they read `weather::storm`; gravity scales `Physics::GRAVITY` in falling and swim buoyancy (`src/player/entity.rs`), and the wading hop out of thick liquids scales with sqrt(gravity) (`thick_jump_force`), so a low-gravity planet is not stuck in a one-block ledge nor a heavy one a trampoline. The map's info panel (`Renderer::draw_hud`) adds gravity (x Earth) and a weather line ("no weather" only when the atmosphere density is 0, else the storminess). Accepted limit: keys `1`-`9` cannot select planet #10 in a 10-planet system (a click works).

`Renderer::render_space` (`src/render/renderer.rs`) delegates every frame to `SpaceRenderer::render` (`src/space/render.rs`), a fully separate forward-rendering pipeline (own shader, `src/space/space.wgsl`; own camera/body uniforms; no G-buffer, no shadows, no atmosphere/fog) — deliberately, so sub-project #2 (below) could replace the placeholder planet bodies with real terrain-shaped impostors without first unwinding a shared pass. It does reuse two things from the planet-mode pipeline: the depth texture (`Deferred::depth`, `deferred::DEPTH_FORMAT`) and the swapchain/surface itself; everything else (shader code, camera/body uniforms, G-buffer, shadows, atmosphere) is separate. It draws a procedural starfield background (full-screen triangle), then the star (see "Star" below), then the planets (sub-project #2, below) and their atmosphere shells. Positions use a **floating origin**: `SolarSystem`/`Planet` store world positions in `f64` (`DVec3`), and every body's GPU offset is computed as `(body_pos - flight.position)` in `f64` before narrowing to `f32` (`src/space/render.rs`'s `render`) — so the camera is always effectively at the origin for rendering, and the view matrix itself is rotation-only (`Mat4::from_quat(flight.rotation).inverse()`, no translation). This avoids the f32 precision loss that would otherwise show up at the system's scale (orbits run out to tens of thousands of units, further than where the main planet engine's own f32-precision note above starts to matter).

There is no separate home planet: every planet is a planet. The game starts on planet #1, or on the first planet of the `--biome` type (`SolarSystem::start_planet_index`), baked synchronously at start-up (`bake_planet` + `install_world`, the same path a capture's background bake takes) and standing at local noon (`noon_spawn`). `Game::loaded_world` is the index of the planet the voxel engine holds — always one. Debug commands (`src/app/cmd.rs` → `SystemRequest`, applied in `src/main.rs`): `/system home` respawns on the start planet (`Game::start_planet`) at noon from anywhere, `/system goto <n> <radii>` jumps into a planet's orbit, `/system add <type> <radius>` appends a planet of that type and radius (20–1000) on the next orbit outward (`SolarSystem::add_planet`, at most `MAX_PLANET_COUNT` = 15 planets; the list holds at most `MAX_PLANETS` = 48 bodies, moons included). You leave and arrive only by flying. Landing and liftoff are seamless (milestone 4, `src/player/landing.rs`): captured space flight hands over to the voxel engine below `LAND_HANDOVER_RADII` (3) from the planet's centre once the voxel world is ready (`loaded_world == i` and `Renderer::view_covered()`), arriving in fly mode at the same eye position, view direction, roll and velocity (`player_pose_from_flight` returns the player's `cam_roll`; pitch clamped to the planet camera's 1.5 rad), and cross-faded: for `HANDOVER_FADE_SECONDS` (1 s, `landing::handover_overlay_opacity`, `Game::landed_at`) the near impostor is alpha-blended over the finished voxel frame, fading out (`Backdrop::handover_overlay` → `SpaceRenderer::draw_handover_overlay`, `fs_planet_overlay`, opacity in `SpaceCameraUniform.screen.w`; recorded after the lighting pass into the frame's encoder, reusing `Deferred::depth` cleared for the impostor's own depth; liftoff is still a cut); above `LIFTOFF_HANDOVER_RADII` (3.5) the voxel engine hands back to captured space flight (`flight_pose_from_player`, roll included). Space mode renders with the first-person planet camera's 80° field of view (`FOV_Y_RADIANS`), so the view doesn't zoom at the handover. Until the voxel world is ready, captured flight is kept above `MIN_CAPTURED_RADII` (2) so it can't sink into the impostor. On planet fly speed scales with altitude (`landing::fly_speed`, `Player::handover_altitude`) up to space flight's cruise/boost speed at the handover altitude, so speed doesn't jump either.

Planet frame and sun (`src/space/solar_system.rs`): `Planet::to_planet_frame`/`from_planet_frame` (and the `rotation_*` variants) convert between space and a planet's own frame — origin at its centre, spinning about +Y by `spin_angle(t) = t * (TAU / day_length_secs + orbit_speed)`. The orbit term is deliberate: it makes the solar day exactly the planet type's `day_length_secs`. `sun_dir_in_planet_frame` is the real star's direction in that frame; the game passes it to `Renderer::render` (always the real star). It uses the one shared game clock, `Game::clock`.

Captured flight (milestone 3 of the landing): space flight lives in a `FlightFrame` (`src/space/solar_system.rs`): `Free` (space) or `Captured(i)` (planet *i*'s frame). `next_flight_frame` captures within `CAPTURE_RADII` (10) planet radii and releases beyond `RELEASE_RADII` (11) — hysteresis, so hovering at the boundary can't flip-flop; `SpaceFlight::change_frame` converts position, orientation and velocity so nothing visibly jumps (velocity is only rotated — the player starts co-moving with the planet). flight keys work in space flight like in planet fly mode (`Controller::space_flight_input`: A/D roll about the view direction, Q/E turn, no sideways movement; `SpaceFlight::roll_rate`/`turn_rate` ramp toward ±`ROLL_SPEED`/`FLIGHT_TURN_SPEED` at `ROLL_ACCEL`/`TURN_ACCEL`, `src/player/smoothing.rs`; pure roll, no banking in space; no automatic levelling in orbit, the roll and roll rate are carried across the handovers instead), `SpaceFlight::update` turns about the ship's own axes (mouse and Q/E yaw about the camera's up, pitch about its right, in free and captured flight alike), and climbs/descends (Space/Shift) about the local radial up while captured (`up` parameter; `None` in free flight, where they follow the camera's own up, since space has no up); space mode renders from `SpaceCamera::from_flight_in_frame`, and every planet impostor is rotated by `Planet::orientation(t)` (its spin). Flight turns with the planet frame's spin (`Planet::spin_rate`, 1.5–6°/s) only close to it: `solar_system::co_rotation` fades it from full below `CO_ROTATION_INNER_RADII` (1.64, the glide ceiling) to none from `CO_ROTATION_OUTER_RADII` (3), `solar_system::counter_spin` undoing the rest each step on position, velocity and attitude — in captured flight (`src/main.rs`) and planet fly mode alike (`Player::spin_rate`, set with `handover_altitude`), so the handovers don't change it. Near the planet the ground holds still and the sky turns, like an aircraft; out in space the ship keeps still against the stars and the planet turns below (co-rotating out there read as the ship being pulled round, stars sweeping past). Capture also starts a background bake (`src/main.rs`'s `start_bake`: `Planet::bake_with_edits()` — the planet's edits from an earlier visit, kept in `Game::edits_by_planet` by `stash_edits` whenever another planet is installed, restored before — plus `impostor::near_impostor_mesh`; start-up and `/system home` bake the same way via `bake_planet`; in space mode a near impostor older than the installed planet's edits, `near_impostor_outdated`, is rebuilt on a background thread and swapped in); a finished bake is installed unless the player has since gone home, landed or been captured by another planet (`bake_still_wanted`; merely leaving orbit again keeps it, so re-capturing the same planet doesn't re-bake) — it becomes the voxel engine's `planet` (`loaded_world = i`), the engine streams from the flight's planet-frame position every tick (`Renderer::update_view`), `Renderer::view_covered()` reports when no required mesh is missing, and the planet's impostor becomes the near impostor (`SpaceRenderer::set_near_impostor`: the engine's own `generate_lod_mesh` in 4 × 4 nodes per cube face, `near_impostor_node_size`: every 2nd column on generated planets, so shape and colours are what the voxel engine's LOD terrain shows). The planet pipeline draws without back-face culling, like the engine's geometry pass: LOD mesh winding isn't consistent, and culling punched holes into the near impostor at cube-face corners and seams. `/system goto <n> <radii>` (permanent debug command) drops the player captured by planet *n*, over its day side at `radii` × radius from its centre.

Star heat zone (`src/space/solar_system.rs`): from `HEAT_ZONE_RADII` (2) star radii inward `star_heat` rises smoothly to 1 at `HEAT_LIMIT_RADII` (1.15, about 450 units above the surface); in free flight `src/main.rs` applies `star_heat_push` (outward, up to `HEAT_PUSH_ACCEL` 48,000 units/s², more than eased boost flight can pull inward) and `keep_off_star` (a hard limit at `HEAT_LIMIT_RADII`, inward speed removed there). Captured flight never meets it: the innermost orbit lies outside the zone. `Renderer::render_space` draws a warm full-screen glow (`update_heat_glow`, the screenshot flash's pass and `fs_flash`, which now takes its colour from `params.yzw`) under the HUD, plus a "Too close to the star" warning from `HEAT_WARNING` (0.35). No damage: space flight has no health.

The space mode UI is a deliberately small HUD (`Renderer::render_space_overlay`, glyphon text drawn in its own pass over the finished space frame, no extra pipeline): the console when open (`Renderer::console_text`, shared with planet mode; its panel is `flash_pipeline` under a scissor rect in `CONSOLE_PANEL_SPACE_COLOR`, the on-screen colour of planet mode's lit panel, and it hides the HUD text under it), the same `FPS: N` readout as planet mode (`Renderer::update_fps` is shared by both render paths, so the counter keeps updating across a mode switch), the same white screenshot flash (`Renderer::update_flash`/`draw_flash`, also shared: the flash starts the frame after a capture, so it's never in the PNG), and a compass strip across the top — a tick bar covering ±90° around the view direction with one label per body (`#<orbit number> <type> <distance to surface>`, e.g. `#3 Ice 3.2k`, in the type's ground colour). Bearings come from `solar_system::compass_bearing` (camera-relative yaw/pitch, so they follow mouse-look); bodies outside the strip pin to its edge with `<`/`>`, `^`/`v` mark targets more than 20° above/below, distances use `solar_system::format_distance`, and labels that would overlap stack into rows. From the default entry point everything is nearly straight ahead, so all the labels (the star and the start system's eight planets, moons too: `#7a`) stack into columns there — expected, not a bug.

### Moons, the system scale and eclipses (`src/space/moons.rs`, `src/space/eclipse.rs`; spec `docs/superpowers/specs/2026-10-12-moons-design.md`, plan `2026-10-12-moons.md`; branch `moons`)
**Scale:** `SYSTEM_SCALE` = 4 multiplies every length of the solar system: planet radii 160–1000, `INNER_ORBIT_RADIUS` 32,000, star radii 7,200–14,400, `HABITABLE_ORBIT` 108,000, cruise/boost 2000/8000 u/s, `HEAT_PUSH_ACCEL` 48,000, `travel::duration`'s reference distance; `MAX_ADDED_RADIUS` 1000. Periods and angles are unchanged (planets #1-#7 of seed 1 are the old ones x4 index for index). Bake costs follow: the largest planet (radius 1000, res 2000) bakes in ~1.7 s release and ~170 MB (`largest_planet_bake_time`, ignored); planet #1 of the start system ~0.7 s.
**Hierarchy:** one flat `SolarSystem::planets` list; a moon has `parent: Option<usize>` (always a smaller index than its own; generated moons follow all planets) and `parent_orbit: Option<OrbitParams>` (its orbit around the parent; `Planet::orbit_radius` etc. stay the parent's, so the star's angular size from a moon uses the parent's orbit), `position_at` nests (parent + circle), `planet_count()` counts planets only, `moons_of(parent)`. `Planet` stays `Copy`. The flat index keys edits, visited flags, bakes and the voxel world (`loaded_world`). **Labels:** `body_label` / `parse_body` (`#3` planet, `#3b` its second moon; letters never panic, a letter past the parent's moons is rejected); `/travel 3b`, `/map 3b`, `/system goto 3b <radii>`, the compass, the map panel and `Universe::location_label` use them. **Generation** (`moons::moons_for`, called by `generate` and `generate_varied`, deterministic per seed, no extra terrain): Hill sphere `r_H / R_p = 1.1 * (a / R_*)` (`hill_radii`, `STAR_DENSITY_RATIO` 0.25), orbits in `[2.5 R_p (MOON_MIN_ORBIT_RADII), 0.5 r_H (MOON_STABLE_FRACTION)]` with consecutive orbits at least `MOON_ORBIT_STEP` 1.4 apart (`moon_orbit_radii`), tilt up to `MOON_MAX_TILT` 5 degrees, radius in `[40, 0.25 R_p]`, counts capped by type (terrestrial 2, Ice up to 6, Shattered and Cratered 1; an inner planet of a big star gets 0), types Cratered 70 %, Ice 12 %, Toxic 9 %, Desert 9 % (the last two only from radius 100), period 150 s * (r / 3 R_p)^1.5 (`moon_orbit_speed`). **Tidal lock:** `spin_rate` = the moon's `orbit_speed`, so `day_length` is its month and the parent hangs fixed in its sky. **Gravity:** `gravity_for_radius` (radius 40 → 0.15, 160 → 0.6, 1000 → 1.3 g, piecewise linear) is `PlanetTraits.gravity` for moons (`moon_traits`) and the base of varied planets' gravity; the player reads `planet.traits.gravity` (falling, buoyancy, wading hop), jump force unchanged. **Capture** (`next_flight_frame`): the nearest body in its own radii wins, so a moon captures only within `CAPTURE_RADII` of its own radius; `moon_takes_over` hands a flight captured by the parent over to a moon it approaches (through `Free` for one call, no ping-pong, no landing onto the parent while a moon is nearer); trips avoid the parent (`travel.rs`), the map spreads moon rings around their parent (`MapLayout`, picking, `map::pick`), the compass lists moons by label (a moon only within 30 parent radii of the camera, `moon_on_compass`); the map labels a moon only when hovered, selected, where you are, its parent is hovered/selected or its ring is over 40 px wide (`shows_body_label`), as `#5a`, and rings never exceed 0.45 of an orbit gap (the biggest parent with six moons accepts overlapping moon markers); captured by a body, the map's "you" ring sits on that body. **Debug:** `/system add moon <n> <type> <radius>` (the console answers "No stable orbit left around that planet." when no orbit fits; seed 1: planets #1 and #3 have no room, #7 does), `/system time <s>` sets the shared game clock (to line up eclipses and phases).
**Sky and eclipses** (`src/space/eclipse.rs` mirrors the WGSL, a constants test `CONSTANTS` and naga validation as for fog/lightning): `family_of(system, body, t)` lists the other bodies of the family (parent, siblings, own moons; at most `MAX_FAMILY` 6, nearest by apparent size first), `pack_family` packs them into `array<vec4, 12>` (`GlobalUniform.family`/`family_info`, `PlanetUniform` for impostors; up to `MAX_OCCLUDERS` 4 occluders per lit pixel). `atmo_sun_visibility` (`src/render/atmosphere.wgsl`: overlap of the star's disc with each occluder's disc, from `disc_overlap_fraction`: none, partial, annular, total, 0 exactly with no NaN at zero separation) multiplies the direct sun in `shade()`, `fs_water`, the precipitation and the impostors, so shadows of moons and parents fall on terrain and on other bodies; `atmo_sky_bodies` draws the family's discs in the sky before the clouds, only where the sky is opaque (the backdrop's impostor takes over where it turns transparent): phase per pixel from the sphere normal under the ray against the star direction, a floor brightness on the unlit side, added to the sky (so the dark side shows the sky), the nearest disc in front where they overlap, and the sun disc hidden through `atmo_family_cover`; the sky dims with `camera_visibility` / `ECLIPSE_SKY_DIM_MIN` (`SKY_DIM_MIN` 0.25 at a total eclipse) through `Atmosphere.sky_dim` (inside `atmo_sky_dome`, so the dome, fog colour, water reflection, env bake and analytic env all follow) and the fill light, the clouds' sun term through `Atmosphere.sun_vis`. With no family (a planet without moons) every new path exits at once and the frame is identical to before (checked by screenshots compared by mean absolute difference against the previous commit's, within run-to-run noise; not byte-identical files). Cost (windowed 1200x900, Shattered #7, lighting median): 1.55 ms before eclipses, 1.66 with one family body, 1.73 with two (+0.1-0.2 ms); frame medians within noise. **Accepted limits:** circular orbits only; no independent weather for moons (they share the weather field), no geysers on Ice moons, no moons of moons, no rings; impostors keep `family_info.z` at 1 (undimmed fill light during an eclipse, a cross-fade step at the handover); no lunar eclipse in the day-sky disc; overlapping occluders are counted twice (the sum is clamped); the travel line ends at the parent's mapped position; a parent is re-baked when returning to it (edits are kept); keys 1-9 cannot select bodies beyond 9 (a click works).
**Open risk (user decision pending, not implemented):** fly and cruise speed is 2000 u/s on every body (`landing::fly_speed` reaches cruise at the handover altitude), i.e. ~50 radii/s at a radius-40 moon (~6 on a normal planet), and captured flight's capture sphere (10 own radii) lies inside a small moon's landing handover distance (3 radii of the moon); a body-relative speed cap in captured flight and planet fly mode (both sides of the handover) is proposed.

### Solar-system map and travel (`src/space/map.rs`, `src/space/travel.rs`; spec `docs/superpowers/specs/2026-10-12-system-map-travel-design.md`)
**Map** (`M` in planet and space mode, `/map [n]` for scripting; `M`/`Esc` close): an overlay over the modes (`Game::map: Option<MapView>`), the game keeps running, the voxel world isn't drawn (`Renderer::render_map` instead of `render`/`render_space`), the keyboard and mouse go to the map (`open_map` releases the movement keys and frees the cursor; `close_map` restores it). `MapLayout`: the orbits evenly spaced from the star (`STAR_MAP_RADIUS`) to `D_MAX`, piecewise linear in the real distance (order and direction kept; ships and travel lines map too — the spec's square root left the inner orbits so close that every planet was a few pixels), one size factor `k` for all planets (the largest at `MAX_FILL` = 35 % of an orbit gap: relative sizes kept, no overlaps). `SpaceRenderer::render` takes a `Layout`: `Real`, or `Map { map, eye }`, where every body's camera-relative offset is `MapLayout::render_offset` = (mapped position − map eye) / k — perspective then shows it at its mapped size while radii, light, clouds, fog and weather stay in real units, so map planets look exactly like the real ones (the camera sits at the origin looking at the star; the star is drawn at `STAR_MAP_RADIUS / k`). Orbit rings (each orbit sampled over its period, so tilts come out right), hover/selection rings and the trip's line are a line-list pipeline (`vs_ring`/`fs_ring`, `RingVertex`; `MAX_RING_VERTS` is the exact budget for `MAX_PLANETS` orbit rings of `RING_SEGMENTS`, a `TRAVEL_LINE_POINTS` travel line and three `CIRCLE_SEGMENTS` circles — going over asserts in debug and is reported, never dropped silently). `MapCamera` orbits the star (drag: yaw/pitch 5°–85°, wheel: zoom down to twice the star's map radius, `MAP_FOV_Y` 50°); `pick_planet` is a ray–sphere test against the mapped spheres, each at least 12 px; `MapView` turns press/release into drag or click (click selects, a second click or `Enter` travels; `1`–`9` select). HUD (`Renderer::draw_hud`): labels, "<- you" on the planet you're on, a "you" ring at your ship's mapped position in space, the selection's info panel (type, radius, day length, liquid, distance, visited — `Game::visited`, every installed world), the help line. Cost: ~1.1 ms per frame fullscreen with the map open.

**Travel** (`Game::travel: Option<Travel>`; started from the map or `/travel <n>`; "You are here." on the planet you stand on): `Travel::Climb` in planet mode flies straight up at `travel::climb_speed` (faster with altitude; the climb moves the player itself and zeroes the velocity before `update_player`, so it isn't integrated twice) until the normal liftoff handover; on the first space frame the cruise is planned (`Trip::plan`, the flight converted to the `Free` frame) and the target's bake starts (in space, so `bake_still_wanted` keeps it). `Trip`: the arrival point is exact in advance (orbits are analytic): the target's position at arrival time plus `ORBIT_RADII` (3.5) radii over its day side through its spin then; a cubic Bézier from the start (along the current velocity or view) to it, approaching radially, bent outward around the star's heat zone; duration `6 + 1.5·log10(distance / 1000)` s, clamped 6–12 s; position by smootherstep along the arc length (LUT) plus the target's motion blended in, `(P(t) − P(t1)) · smootherstep`, so the trip ends co-moving with the planet (0 at both ends; the end velocity is the planet's). After the Bézier bending a final check samples the flown path; if it still touches the heat zone both inner control points swing out to one side of the star, wider each time. The view (`Trip::view_rotation(system, t, current)`) turns the current rotation each frame by the shortest arc to a desired direction — from the view at plan time into the flight direction over the first 15 %, along the flight, toward the planet over the last quarter — so the player's roll is kept and no heading is singular; the arrival keeps that view (turned into the planet frame). While a trip runs, the space-mode autopilot arm (`space_arm(travel) == SpaceArm::Autopilot`; the manual arm, the only one calling `next_flight_frame`, asserts `Manual`) sets the pose and skips manual flight, capture/release and the heat push; on arrival: `Captured(target)` at the orbit point, at rest relative to it, looking at the planet. Cancel: a movement key, `F` (it would otherwise start a landing against the climb), `Esc` or a real mouse turn → free flight at `cancel_velocity` (≤ boost speed, roll and turn rates zeroed). A mouse turn counts only when the mouse turns the view (`mouse_turns_view`: first person, cursor captured, console and map closed), summed (`TripMouse`) past `TRIP_MOUSE_CANCEL` (40 px) after a `TRIP_MOUSE_GRACE` (0.4 s) that restarts whenever the mouse can't turn the view (trip start, map just closed); during a trip the tick drops the controller's mouse delta, so nothing piles up into a jump. `M` during a trip shows the map with the trip's line; the cursor stays free while the map is open (the tick's lock requires `map.is_none()`, and liftoff/`/system goto` with the map open write the captured state into `MapView::restore_mouse_released` instead). `/system home` and `/system goto` end a running trip. HUD: "-> #n Type  Xs" under the compass (`Renderer::travel_hud`).

### Galaxy (`src/space/galaxy.rs`, `src/space/universe.rs`; spec `docs/superpowers/specs/2026-10-12-galaxy-design.md`)
`--seed` picks the **galaxy**: `Galaxy::generate(seed)` computes `GALAXY_SYSTEMS` (300) entries up front — position in light-years (two spiral arms, the angle linear in the radius (`ARM_TWIST`), to `GALAXY_RADIUS_LY` 50, a quarter of the systems in a core of `CORE_RADIUS_LY` 8, flat, at least `MIN_SPACING_LY` 1.5 apart by rejection sampling), system seed, star type (`star_type_for(system seed)`, so the galaxy view shows the star you find) and a syllable name. Entry 0 is the start system and has the galaxy seed itself, so `--seed n` still gives the solar system it always gave. Every system except entry 0 is varied (`SolarSystem::generate_varied`, see Varied systems; 3-10 planets, traits per planet); entry 0 keeps `generate` (8 planets, neutral traits). A `SolarSystem` is generated only on the first jump there (planets' height maps only on approach, as before). `Universe` holds the catalogue, the current system's index and the **parked** systems (`switch` parks the current one and hands back the target, generated on first use; "You are here." for the current one; `known(i)` for systems generated earlier, else "unexplored"). `Game.system` stays the current system. The voxel world is tagged with its system (`Game::loaded_system` next to `loaded_world`): every space-mode check (bake trigger, streaming and the landing handover, near-impostor rebuild) asks for `(universe.current, i)`; edits and visited flags are keyed by (system, planet) (`edits_by_planet`, `visited`); bakes carry their system (`BakedPlanet::system`) and `bake_still_wanted` drops one for a system left behind. **Jump** (`/jump <n>`, the galaxy view; spec `docs/superpowers/specs/2026-10-12-warp-jump-design.md`): a light-speed flight. `Jump` (`main.rs`) runs in stages: `Climb` (from the surface the travel climb to the liftoff handover; in space it turns into the flight on the next frame), `Fly` (the timeline in `space/warp.rs`: duration `jump_duration(ly)` = clamp(3 + 5·ly/100, 3, 8) s; phases align 20 % / departure 20 % / light speed 30 % / arrival 30 %; `speed` and `scene_fade` ramp 0 → 1 over the departure and back over the arrival; the flight converts a captured flight to `Free` first, eases the ship's velocity out over the align phase (no dead stop after a liftoff climb), then turns the view incrementally from where it looked to the galaxy direction of the target over the align phase, roll kept), and `HomeFadeIn` (`/system home`: at the end of the flight the start planet is installed under a short black fade, `HOME_FADE_SECS` 0.4, `set_fade`). The switch comes once, at `SWITCH_AT` (55 %, inside the light-speed phase, `crosses_switch`): the current system is parked and the target taken, the space renderer's per-system caches are cleared (back in the voxel world's own system its near impostor is rebuilt), you're moved to the arrival point at 1.3 × the outermost orbit facing the system you came from (`Universe::arrival_pose`; the view keeps its aligned rotation, which already looks along the travel direction at the new star, so the streaks don't turn); trip and bake are cancelled. While the jump climbs or flies it owns the controls (`jump_blocks_input`: key presses, clicks, mouse look, `Esc`, `M`, `G` ignored; key releases pass, `jump_swallows`, so a key held into the jump doesn't stick). Console commands that would move the player or open an overlay go through `refused_during_jump` and answer "Jump in progress." (console and status line): `/system home|goto`, `/map`, `/galaxy`, `/travel`, `/jump` while it climbs or flies — except `/system home` from another system, which `Jump::queue_home` decides (a jump already going to the start system goes home on arrival) — and during home's fade-in everything but the overlays. `/jump` requests are handled after the system requests, so `/system goto …; /jump …` in one tick (`--bench --exec`) jumps from the orbit. The start shows "Jumping to <name>…" in the status line (from the surface the climb shows it), the flight in the space HUD. **Streaks:** `space/warp.wgsl`, its own pipeline in `SpaceRenderer` (`draw_warp`, a full-screen pass after the space scene, before the HUD, from `Renderer::warp` = (speed, scene fade, travel direction)): per pixel the view direction as (angle from the vanishing point, angle around it); 220 sectors around it, each streaming outward at its own pace and phase (so no rings); one star in `DENSITY` (4 %) of the cells (`RINGS` 0.12 wide along log(angle); an integer PCG hash — the old sin() hash degenerated at large cell numbers), drawn as a radial streak whose length (log-angle units, 0.04 + speed·0.8·(0.5 + angle), capped at `MAX_LEN` 0.9, × 0.5–1 per star) grows with the speed and the distance from the vanishing point, its tail fading out; the loop walks the cells cell0 … cell0 + ceil(len / RINGS) (`MAX_CELLS` 9) whose streaks can reach the pixel; per-star brightness, a constant angular width on screen, thinned right at the vanishing point, white-blue to orange. The outward flow is integrated on the CPU (`warp::advance_flow`, `Renderer::warp_flow`: dt·(0.4 + 2.6·speed)), not time × speed, which threw the streaks around every frame while the speed ramped. The compass markers and the lens flare fade with the scene (× (1 − fade), `Renderer::warp_scene`), so nothing shows the switch; a faint blue glow around the vanishing point and red-shifted edges at speed; alpha = the scene fade (premultiplied `One` / `OneMinusSrcAlpha`), so the scene fades out under the streaks and back in. Cost: none measurable (frame median 1.4–2.0 ms over a jump in five fullscreen `--bench 4 --label "warp jump" --exec "/system goto 1 6; /jump 200"` runs, 1.2–1.6 ms before the streak fix; plain space flight 1.4 ms). The black fade layer (`set_fade`) stays for the home step. **Galaxy view** (`G` or `/galaxy [n]`; `G`/`Esc` close; `M` and `G` switch between it and the system map, and `/map` and `/galaxy` close the other, so only one is ever open): another `MapView` with `MapCamera::galaxy_view()` (the zoom range is per camera now), galaxy positions in view units (`LY_TO_VIEW`: the galaxy's radius to `D_MAX`); `SpaceRenderer::render_galaxy_view` draws the systems as instanced screen-sized star sprites (`GalaxyStarInstance`, `vs_galaxy_star`/`fs_galaxy_star`, added over black, no starfield: the galaxy's own stars are the picture; colour: the star type's surface colour normalised and saturated, size by the type's radius, at least 2.5 px) plus marker rings (current: green, hover: yellow, selection: white); `Renderer::render_galaxy_map` adds labels (`shows_label`: current, hovered, selected and visited systems), the info panel (name, catalogue number, star type, distance in ly, visited, planets — each type once, `distinct_kinds` — or "unexplored"; as wide as its longest line, `panel_width_px`) and the help line. Picking: `pick_system` (each star at least 10 px); `map::pick` (also the system map's) takes the sphere the ray passes most centrally, relative to its radius, so among overlapping markers the one closest to the cursor wins, ties to the front one. `fs_galaxy_star` applies its falloff once (disc with an inner glow, a faint glow² halo outside it). Cost: ~0.8 ms per frame fullscreen with the view open.

### Star, star types, sunlight and lens flares (`src/space/solar_system.rs`, `src/render/star.wgsl`, `src/space/space.wgsl`, `src/render/flare.rs`, `src/render/flare.wgsl`)
The solar system has one star of a `StarType` (RedDwarf, Orange, Yellow, White, BlueGiant; `StarTypeDef`: surface/limb colours, radius 7,200–14,400 (`SYSTEM_SCALE`) so the heat zone stays off the innermost orbit, granulation, sunspots, corona colour/size, planet sunlight), picked by `star_type_for(seed)` (a hash of the system seed; `--seed <n>`, default 1, which is Yellow). Sunlight is no longer a constant: `Atmosphere.sun_color` comes from the type's `sunlight` (engine: `BiomeUniform.sun.rgb`; impostors: `PlanetUniform.sun_color`), bright and only moderately tinted; Yellow is the old `SUN_COLOR` `(1.6, 1.5, 1.3)`. `src/render/star.wgsl` (prepended after `src/render/atmosphere.wgsl` to the scene, space and flare shaders; closed-form terms mirrored in `src/space/star_shading.rs` for tests) has `StarLook`, `star_surface` (limb darkening `1 − 0.6·(1 − mu)` shifting toward the limb colour, boiling granulation, drifting sunspots) and `star_corona`. In space mode the star is one camera-facing quad (`star_pipeline`, `vs_star`/`fs_star`, `StarUniform`) ray-cast per pixel: the disc writes its true sphere depth (reversed-Z `frag_depth`), the corona fades out within the quad (`length(quad)`; up close a closest-approach falloff left a square) and writes a tiny depth so planets in front hide it; a minimum angular radius (`STAR_MIN_ANGULAR_RADIUS`) keeps a distant sun a glowing point. It is drawn right after the background, so planets and their atmosphere shells go over it. Lens flares (`src/render/flare.wgsl`, own pipeline, `Renderer::update_flare`/`draw_flare`, drawn before the HUD text in both frames): a starburst, six ghosts on the line from the sun through the screen centre (`flare::GHOSTS`, `ghost_position`) and a halo ring, tinted by the type; intensity `flare_intensity(visibility, on_screen_factor, angular_radius)` capped at `MAX_FLARE`; visibility = 9 taps around the sun in the vertex shader — the space depth buffer (`Deferred::depth`, now also `TEXTURE_BINDING`; nothing nearer than the star's expected depth from `render::star_on_screen`) or the planet G-buffer distance (`Deferred::dist_view`, 0 = sky) — times `atmo_cloud_shadow` along the sun ray in planet mode; in planet mode it fades out as the sun sinks below the planet's geometric horizon (`flare::horizon_visibility`, across the sun's own disc; high up the horizon dips below the local horizontal, so the flare matches space mode at the handover) and is off underwater; scaled by `1 − heat` in the heat zone. The taps span half the sun's apparent radius for the camera's real field of view (`flare::tap_radius_px`: 80° first person, 45° third person).

### Planet impostors in space (sub-project #2) (`src/space/impostor.rs`, `src/space/render.rs`, `src/space/space.wgsl`)
Builds on the space-mode foundation section above: planets are no longer flat-shaded placeholder spheres, they're meshes displaced by the same noise the player's actual planet uses — without paying for a full `PlanetData`/heightmap per planet, which would defeat sub-project #1's "many planets, bounded memory" design. `Planet` (`src/space/solar_system.rs`) carries a `noise_seed: u32` (`noise_seed_for(seed, index)`, a bit-mixing hash independent of `planet_radius_for`'s hash so a planet's size and its terrain shape don't correlate); without a per-planet seed every planet would sample the same noise field and look identical apart from radius and palette. `src/space/impostor.rs`'s `generate_planet_mesh(planet, subdivision)` builds on an `src/space/icosphere.rs` unit sphere: it constructs a `TerrainShape::new((planet.radius * 2.0) as u32)` and `NoiseGenerator::new(planet.noise_seed)` — both now `pub(crate)` (previously private to `src/planet/noise.rs`, the single-planet engine's own module) — and calls `shape.height(&generator, dir)` directly per vertex, with no baked `PlanetTerrain` heightmap in between. Per-vertex colour is a simplified, slope-free height-banded rule (`ROCK_LINE`/`SNOW_LINE` fractions of the planet's own peak relief, `shape_relief()`) rather than `material::natural_type()`, which needs neighbour-slope data that's meaningless on this sparse, widely-spaced mesh; underwater vertices (height < 0) take the active `PlanetTypeDef`'s liquid colour (or the beach colour on liquid-less planets). Displacement is clamped to sea level on every planet type (see the far-impostor note below).

The far (noise) impostor matches the voxel engine's terrain shape: radius `voxel_resolution() / 2` and `TerrainShape::new(voxel_resolution(), ..)` (the same rounded resolution `Planet::bake()` uses), heights through the engine's exponential layers (`CoordSystem::get_layer_radius_f`), and oceans/liquid-less basins flattened to sea level on every planet type, lakes to their level in the liquid colour (`TerrainShape::new(.., with_lakes)` for liquid types, like the bake), like the engine's distant LOD meshes (which clamp to each column's `water_level`); rock/snow bands at src/planet/material.rs's 45%/62%.

Planets get their own `planet_pipeline`, one real vertex/index buffer per `(planet index, subdivision)` in `planet_meshes` (built lazily by `ensure_planet_mesh`, cached for the process lifetime — a planet's mesh is regenerated once per subdivision level it's ever been seen at, not every frame), and a **dynamic-offset uniform buffer** (`planet_uniform_buf`, `has_dynamic_offset: true`, stride rounded up to `min_uniform_buffer_offset_alignment`) carrying each planet's camera-relative offset, light direction and atmosphere colour, one aligned slot per planet. Every slot is written before the render pass begins: `render()` loops over `planet_uniforms` calling `queue.write_buffer` first, then opens the pass and does a second loop that only calls `set_bind_group`/`draw_indexed` with a different offset into that already-fully-written buffer per planet — not per-draw `write_buffer` calls interleaved with the draws. `queue.write_buffer` takes effect relative to the *queue's* execution order, not to when the encoder recording the pass is later submitted; writing a per-planet uniform and immediately drawing with it, repeated inside one not-yet-submitted render pass, would mean every draw ends up reading only the *last* write by the time the encoder is actually submitted (same hazard the star's body-storage-buffer path was already built to avoid).

`SpaceRenderer::render` draws from a `SpaceCamera` (space position, orientation, vertical field of view: `from_flight` in space mode, `on_system_planet` for the planet-mode backdrop) and a `SpaceContent` (`Everything`, `AllButPlanet(i)` — the planet the voxel engine is drawing). Depth is reversed-Z with no far plane (`projection`: `perspective_infinite_reverse`, compare `Greater`, clear 0; the `Depth32Float` buffer keeps about the same relative precision at every distance), so every body is drawn at its real distance and size: `/system add` puts planets on orbits millions of units out, and from out there the star and the inner system are farther still. (An earlier far plane with far bodies pulled in to it sorted them by their shrunk size and let a far planet's back show through its front.) The planet-mode backdrop shares `Deferred::depth`, which the geometry pass clears again, so the reversed values never meet the engine's own `Less` depth test.

LOD is distance-over-radius, re-evaluated every frame per planet (`subdivision_for_distance` in `src/space/render.rs`): coarsest icosphere subdivision 2 beyond `LOD_MEDIUM_DISTANCE_MULTIPLIER` (13×) the planet's own radius, subdivision 4 between that and `LOD_NEAR_DISTANCE_MULTIPLIER` (6×) radius, subdivision 5 inside 6×radius — thresholds scale with each planet's own radius (not a fixed world-space distance), so a big and a small planet switch tiers at the same apparent angular size. Since planet radii here run 160–1000 (`MIN_PLANET_RADIUS`/`MAX_PLANET_RADIUS`, `src/space/solar_system.rs`; moons and added planets go down to 20–40), that's roughly 960–6000 units for the near-tier threshold (6×radius) and 2080–13000 for the medium-tier threshold (13×radius). Crossing a tier just picks a different cached `(index, subdivision)` mesh — there's no fade/animation between tiers like the main engine's `LodAnimator`.

Impostors are lit like the voxel engine (milestone 5 of the landing): `fs_planet` shades in the planet's own frame (`planet_frame_camera`/`planet_frame_light`) with the engine's `shade()` terms minus ray-traced shadows, caustics and grain — linear albedo, `SUN_COLOR`, sky ambient, rim, cloud shadow, air fog, clouds in front of the surface — and ACES/gamma, all from src/render/atmosphere.wgsl with the planet type's `AtmosphereDef` colours (`PlanetUniform`). A per-planet atmosphere shell (`vs_atmosphere`/`fs_atmosphere`, back faces of the unit icosphere at `ATMOSPHERE_SHELL_RADII` = 2.3, depth-tested behind the planets, premultiplied blend, no depth write, so drawn farthest first: `back_to_front`) draws the sky the engine would show along rays that miss the planet: limb glow and clouds beyond the limb. Cloud time is `SpaceCameraUniform.screen.z` (shared clock mod 3600, like the engine), so clouds sit in the same places on both sides of the landing handover. Lava glows on impostors like the engine's water pass draws it: vertices in the planet type's glowing-liquid colour (`PlanetUniform.glow`) are emissive at `glow_emission` (`lava_emission`: fs_water's look for `LAVA_TYPICAL_DEPTH`), unlit, so the night side's lava glows too.

This milestone was verified manually (screenshots, no automated visual test) by temporarily anchoring the space entry point near a planet instead of the default far-away vantage — see this plan's task-5 report for exact screenshots and findings. Only the near tier (subdivision 5, 900 units) and coarse tier (subdivision 2, 5000 units) were previewed via debug-repositioning; the medium tier (subdivision 4) was not independently visually captured, only covered by the existing `subdivision_for_distance` unit tests.

### Low-poly terrain (`src/meshing/lowpoly.rs`)
Style switch: `TerrainStyle` (`Cubes`, `LowPoly`, `Hex` — the default for now, see Hex columns), read with `style()` at `build_chunk` / `generate_lod_mesh` / `generate_lod_morph` and passed down; `/style [hex|lowpoly|cubes]` sets it and calls `force_reload_all`. Density: `natural_density` = `smooth_height − layer + 1`, linear and unclamped (solid above `ISO` 0.5), so the surface over a column centre is at layer coordinate `smooth_height + 1` (block tops on flat ground) and between columns it interpolates their heights at any steepness (a 0..1 clamp used to pin steep crossings to the midpoint: stair steps whose near-vertical risers turned rock and read as holes); mined cells are empty (`MINED_DENSITY`), and so are the natural cells above a mined column top (`Field::carved`: in a dip the smooth surface lies above the top block, so cell h + 1 is drawn solid though it is air, which can't be mined), and edges into them put their vertex half-way, on the block boundary; `Field::sample` is the one density both the mesher and the cover check use; `crossing` / `surface_radius` give the same surface for the LOD meshes. `build_chunk_lowpoly` is dual-grid marching cubes (Bourke tables in `src/meshing/mc_tables.rs`) with unshared vertices and a flat facet colour from `material::lowpoly_material` (shares `material_band` with `surface_type`) or the subsurface type on pit walls, `COVER_DARKEN` for covered facets, and placed blocks drawn as cubes via `add_voxel_with`, culled only against placed blocks. Cell ownership: a chunk owns a cell if it owns the smallest (face,u,v) of the cell's four columns; at cube-face corners the fourth column is stepped from the in-face neighbour, and the three-face corner cell drops collapsed/duplicate triangles (closed on `c1`). LOD: `lod_sample` takes a `TerrainStyle` (smooth corner heights through `surface_radius`, shifted in edited chunks by how far edits moved the column's top, `surface − effective_height`, so edited chunks don't sink a layer; water clamp at `water_level + 1`; facet material colours, or the top block's own colour where an edit moved the top). Shading: `fs_geom` takes the derivative normal and `flat_color` when `LocalUniform.params.w` = 1; `fs_planet` is always faceted via `facet_normal`. Ray-march shadows stay cube-shaped (accepted); hardware shadows follow the facets. Fixed poses for comparisons: `VOXANET_POSE_ALT` / `VOXANET_POSE_PITCH`. Water on low-poly shores (`MeshGen::build_water_styled`, `shore_level`): the drawn terrain crosses the water level between column centres, so in low-poly style the water plane reaches one column onto the land beside every water column (at the highest neighbouring water level, if the column is solid at that level — a column dug out beside a lake keeps its wall of water), hidden where the terrain is higher; the coastline is where the smooth terrain meets the water instead of column steps, and dry shore columns drawn below the water level (≈ 9,400 on the start planet) are no longer unflooded dips you could look into and under the water surface. Gameplay water (`holds_water`, swimming) still follows the blocks. Known quirk: `CoordSystem::neighbor_column`'s diagonals are unreliable where only one axis crosses a cube-face edge; use `neighbour_columns` (the smooth bake, the shore water, `chunks_to_refresh` and the mesher all step diagonals from the in-face neighbour).

### Hex columns (`src/planet/hex.rs`)
A third terrain style and the default for now (`lowpoly::STYLE`), `/style hex`: the voxel world as a honeycomb of hexagonal prisms. Column (u, v) is hex cell (u, v), every odd row shifted half a column, so heights, edits, chunks, LOD and the water rules are shared with the other styles; cells are 1 wide with points reaching ⅙ into the neighbouring rows (about 13 % flatter than regular hexagons, area 1). Across the four seams around Z (the ring: faces +Y, −Y, +X, −X, `hex::ring`) the honeycomb continues (spec: `docs/superpowers/specs/2026-10-11-hex-ring-seams-design.md`): faces −Y and +X shift their odd rows left instead of right (`hex::mirrored`), so at every ring seam one face's odd rows end with a cell reaching half a column onto the next face and the other's with the half-column gap it fills — one whole hexagon per odd row, owned by one column. Its corners stay exact sixths in the owner's extended coordinates (u6 in −3..=6·res + 3), mapped onto the next face by `hex::ring_wrap` (table `hex::ring_neighbour`; inverse `hex::ring_extend`) through `CoordSystem::get_direction_hex`, which `get_vertex_pos_six` uses (`get_direction_f` still clamps: hex code must not use it for corners or centres). `hex::cell_at(face, u, v)` returns the owning column, possibly on the next ring face. At the seams to ±Z the honeycomb is cut off straight (first/last rows squared off; on the ±Z faces an odd row's last cell is cut at u = res, and the half-column gap before its first cell at u = 0 is cut into three triangles along the neighbouring hexagons' edges extended to the border, `hex::border_gap`: the upper and lower ones to the first cells of the rows above and below, the middle one to the odd row's own first cell, which gets a point at the border — the only split that keeps every cell convex); those seams' cells don't line up. Every cell is convex (`hex::tests::every_cell_is_convex`). `src/planet/hex.rs` is pure face-space geometry with corners as exact integers in sixths of a column (`cell_at`, `outline`, `edges`, all taking the face). Unlike low-poly, the hex cells are the blocks: the geometry lives on the planet, `PlanetData::cells: CellShape` (`Square`/`Hex`; `/style` sets it together with the global look, `install_world` copies it onto newly baked planets), and `lowpoly::style_for(data)` dispatches the mesh entry points on it (hex → `build_chunk_hex`/`add_voxel_hex`, hex water fans; LOD meshes are the cube-style heightfields, not faceted). **Gameplay code asks `PlanetData::cell_at`/`cell_local`, not `CoordSystem::pos_to_id`** (the square primitive; streaming and the shadow window keep it): the raycast, `overlaps_block`, `is_solid` (the 5 % shave off each hex wall), water depth, ground block, landing, the fly floor and spawning. `PlanetData::cell_local` returns the owning column and u, v in its face's (extended) coordinates, so physics' wall distances hold in a reaching cell's far half. `PlanetData::hex_walls` gives a cell's walls with the column across each; across a ring seam the neighbour is exact (`hex::edges`), across a seam to ±Z the next face's column is found in world space and border walls come in pieces ⅙ long (every cell boundary of both faces lies on that lattice), so both sides share vertices (no T-junction cracks); `column_neighbors` is the style's side neighbours (4 or 6). Tests: `hex::tests`, `common::hex_tests` (seam walls pair up), `gen::hex_mesh_tests` (the planet mesh is closed: every edge used an even number of times — 4 where a seam point has two cells per face alternating high and low), `physics` `hex_collision_follows_the_hex_cells`; `gen::cube_fingerprint` pins the cube style's meshes. Accepted: ray-march (non-ray-tracing) shadows stay square-celled (`src/render/rt_shadow.rs`); the planet impostors stay faceted.

### Block bevels (`src/meshing/bevel.rs`)
Cube and hex block faces are drawn with rounded edges and darkened joints, shading only (spec: `docs/superpowers/specs/2026-10-09-block-bevels-design.md`). Every vertex carries `Vertex::edge`: its distances (world units, f16, two `Float16x4` at locations 7 and 8, since `LodMorph` uses 4–6) to up to eight bevelled edges of its face; `Vertex::NO_EDGE` (1e4) for none: low-poly facets, LOD, water, impostors, overlays. Distance to a line is affine on a flat triangle, so it interpolates exactly. `MeshGen::quad` fills slots 0–3 for every cube face (`bevel::quad_edges`, mask `[true; 4]`); hex top and bottom fans keep their shared vertices, each measuring every side of the cell (slot = side, `bevel::polygon_edges`; `bevel::polygon_lines` merges a border side's one-sixth pieces into one side; at most 8 sides per cell); a fan's distances interpolate exactly only over a convex polygon, which is why every hex cell is convex (a notched border cell once drew dark groove spikes into itself along the seams), and hex wall pieces round off only the ends that are cell corners. Unsharing the fans instead cost twice the hex geometry pass. `fs_geom` (`bevel_normal`, after the low-poly branch, so placed cubes in low-poly chunks are bevelled and facets aren't) solves each edge's in-plane direction from screen derivatives, tilts the normal on a quarter circle (45° at the edge, so neighbours form a V groove), darkens the albedo toward the edge and fades both out below ~2 px. `GlobalUniform.bevel` = (width, cavity); defaults 0.06 / 0.2 (`BevelSettings`, `Renderer::bevel`); console `/bevel [on|off|width <0-0.25>|cavity <0-1>]`. Cost: the 56-byte vertex (was 40) adds ~1 ms to the geometry pass at 800×600 with 240 chunks in view, in both styles; the shading itself is negligible.

### Film grain and vignette (`src/render/film.rs`)
A camera look over the finished frame in both modes, so the landing handover doesn't add or drop it: `fs_film` (`vs_film`, `src/render/shader.wgsl`) outputs one factor, `0.5 × vignette × (1 + grain × noise)`, that a "2× multiply" blend applies (`out = 2·src·dst`, alpha kept), so grain brightens as much as it darkens and the frame keeps its mean brightness. Noise is a PCG hash of the pixel and the millisecond clock (a new pattern every frame); the vignette is round on screen (aspect in the uniform), darkening from 40 % of the centre-to-corner distance. Parameters ride in a `LocalUniform`'s params (grain, vignette, time, aspect; `Renderer::update_film`, the flash pipeline's layout). Planet mode draws it in the lighting pass right before the console (`film_pipeline_depth`, that pass has the G-buffer depth attached; the lens flare comes after it, in the HUD pass), space mode in its HUD pass after the lens flare (`film_pipeline`); screenshots include it. Defaults grain 0.2 (the maximum; 0.04 was invisible), vignette 0.25 (`FilmSettings`, `Renderer::film`); console `/film [on|off|grain <0-0.2>|vignette <0-1>]` (setting a value turns it on; off keeps the values). Costs ~0.02 ms.

### Ray-traced ambient occlusion (`src/render/ao.rs`, `src/render/rt_hw.wgsl`, `src/render/hw_rt.rs`)
Progressive and budgeted, because a ray query costs ~10 ns on the reference GPU (Intel Arc iGPU, Mesa) whatever its length: per-texel AO was 33 ms per ray in fullscreen. Each frame, in the hardware shadow pass's compute pass after `cs_shadow` (which writes `(shadow, distance, 1)`): `cs_ao_sample` casts `rays` (default 2) cosine-weighted AO rays for **one texel per `ao::BLOCK`×`BLOCK` (4×4) block** of the shadow targets, at `ao::sample_offset(frame)` (4×4 Bayer order, all 16 positions in 16 frames; each sample's ray rotation and elevation jitter come from a PCG hash of (texel, frame) — interleaved gradient noise shifted per frame gave neighbouring texels correlated direction sequences that accumulated into diagonal screen-space stripes), closest hit within `radius` (default 3 blocks), weighted `(1 − t/radius)²`, faded out with camera distance from 150 to `ao::FADE_END` (400) units, no rays beyond (there AO is under a texel, and on large planets the morphed LOD terrain begins, which the TLAS holds unmorphed); `cs_ao_accumulate` adds it to a running mean per texel at shadow resolution (`HwRt`'s ping-pong pair, `(mean, count, distance)`, count capped at `samples`, default 64); `cs_ao_fill_h`/`_v` fill that sparse accumulation depth-aware (taps ≤ 1 texel apart — a coarser step skipped the sparse samples — flat Gaussian, radius from the local sample count, see below; no world-space minimum, which close up forced the widest fill over the whole screen) into `RtBlur::ao_out` `(ao, distance)`, group 2 binding 1 of the scene, which `shadow_ao_at()` upsamples with the shadow's taps. **Temporal reprojection** keeps the accumulation while the camera moves: `cs_ao_accumulate` projects each texel's world point with last frame's view-projection (`AoFrameParams.prev_view_proj`/`prev_cam`, kept in `Renderer::prev_ao_view`; mirror `ao::reproject`), reads the history bilinearly from the four texels whose stored distance matches the point's distance from last frame's camera (2 % + 0.02, widened by the surface's own distance change per texel, `depth_slope`, read only when a tap fails the plain test, so grazing surfaces keep their history; others are silhouettes or disocclusions and start fresh; the count is not renormalised, so a history only partly backed by valid taps counts for that share) and caps its count by the texel's screen motion (`ao::motion_cap`: `samples` 64 while still, toward `motion_slow` 32 up to half a texel, `motion_fast` 4 from 8 texels), so moving views stay calm and responsive. The fill radius follows the centre texel's sample count (`ao::fill_radius_for_count`: 8 texels with none, down to 1.5), passed from the horizontal to the vertical fill pass. Full resets (`ao::AoProgress::advance` → frames 0) only on AO settings, target size, block edits and full reloads (`Renderer::edit_epoch`, bumped in `refresh_neighbors` and `force_reload_all`); camera movement and chunk streaming don't reset. A chunk or LOD mesh coming or going within reach of the AO (`ao::within_ao_reach`) bumps `Renderer::ao_geometry_epoch` instead, which lowers the cap while still to `motion_slow` for `ao::REFRESH_FRAMES` (120) frames (`ao::AoRefresh`), so AO that changed without the depth changing fades in ~32 frames instead of ~1000, without a full reset's flash. The debug overlay's `AO` line shows the frames since the last full reset. When RT AO isn't running, `RtBlur::clear_ao` sets the texture to 1. Each AO stage has its own group-1 bind group with distinct bindings, so no texture is read and written in one dispatch. `shade()` scales the ambient and rim light by AO (not the sun; `fs_water` uses only the shadow). Exactly one kind of AO: the mesher's per-corner vertex AO on cube and hex top faces (`gen::VERTEX_AO`, read once per chunk build; `build_chunk_cubes_with` / `build_chunk_hex_with` take it explicitly, which tests use instead of the global) is on exactly when RT AO isn't (`ao::vertex_ao_wanted`: no ray queries, `/hw_shadows false` or `/ao off`); `Renderer::apply_ao_state` switches it and rebuilds the meshes. Direction brightness, the 0.15 sky factor, `COVER_DARKEN` and `LOD_OCCLUSION` stay either way. Console `/ao [on|off|radius <0.5-8>|rays <1-16>|strength <0-1>|samples <1-256>|motion <fast> <slow>]` (1 ≤ fast ≤ slow ≤ 256). Keep the AO loop's `var rq: ray_query` declared before the loop: declared inside, Mesa's Intel (Arc) driver lost the device compiling `src/render/rt_hw.wgsl` (valid WGSL; `hw_rt_shader_is_valid_wgsl` guards it). Cost, fullscreen 1920×1200 (shadow targets 1549×968), "Rays" (shadow + AO) minus AO off: ~2.5 ms with sky in view, ~4.3 ms still / ~4.9 ms moving looking at nearby ground (worst case); reprojection adds ~1 ms (four history taps per texel); per-texel AO was 88 ms.

### Plastic shading (`src/render/plastic.rs`, `atmo_plastic` in `src/render/atmosphere.wgsl`)
Every block is glossy toy plastic (spec: `docs/superpowers/specs/2026-10-10-plastic-shading-design.md`). `atmo_plastic` (shared by `shade()` and the impostors' `planet_color`; closed-form terms mirrored and tested in `src/render/plastic.rs`) adds a GGX sun highlight (Trowbridge-Reitz, Schlick Fresnel with `PLASTIC_F0` 0.04, Smith-Schlick visibility; lit by the sun × the **hard** shadow × cloud shadow, so none in full shadow) and a Fresnel-weighted sky reflection (`env`, the environment colour along the reflection: in `shade()` the pre-filtered environment map below, on the impostors and with `/plastic env off` `atmo_env_analytic` — the sky dome × opacity, the ground colour below the local horizon, blended toward the ambient with roughness as a cheap pre-filter; × AO), the diffuse terms scaled by `1 − strength · reflection · F`. The reflection has its own weight (`/plastic reflection`, default 0.15): at the physical ~13 % a bright bluish sky washed the block colours out; the highlight keeps the full strength, and lands on the bevels' tilted edge normals as bright edge lines. Roughness per pixel: `fs_geom`'s `plastic_roughness` writes a new `R8Unorm` G-buffer target (`gloss`, `GeomOut` location 3, group 3 binding 7): the base roughness, duller in low-frequency smudges (`value_noise3` over the world position, all geometry) and along sparse hairline scratches in face coordinates from the bevel edge distances (one candidate per block face, kept inside its cell, faded below a pixel; cube and hex faces only). Overlays without a G-buffer use the base roughness; impostors get base roughness, strength and reflection (`PlasticSettings::impostor_uniform` → `PlanetUniform.plastic`), no imperfections. `GlobalUniform.plastic` = (roughness, specular strength, smudge, scratch), `plastic_ext.x` = reflection, `.y` = environment map on. Console `/plastic [on|off|roughness <0.05-1>|specular <0-2>|smudge <0-1>|scratch <0-1>|reflection <0-1>|env [on|off]]`; defaults 0.35 / 1.0 / 0.3 / 0.2 / 0.15; off = specular 0, exactly the old diffuse look. Cost (fullscreen): lighting +0.14 ms, geometry +0.25 ms (scratches). The water pass has its own reflection and is unchanged.

### Pre-filtered environment map (`src/render/env_map.rs`, `src/render/env_filter.wgsl`)
The plastic reflects the sky around the camera from a GGX-pre-filtered cube map (spec `docs/superpowers/specs/2026-10-11-env-map-design.md`): one texture read per pixel instead of the analytic sky in one direction. Content: premultiplied `(rgb · a, a)` — the sky dome × opacity (no sun disc: the sun is the GGX highlight) with the clouds composited in at the map's texel size (`atmo_clouds`, as `fs_water` reflects them), coverage `a = smoothstep(-0.1, 0.1, dot(dir, up))` above the camera's horizon; below it the reflected ground is each pixel's own bounce colour, which can't be baked, so `shade()` uses `env = e.rgb + (1 − e.a) · ground`, and rough surfaces blend blurred sky into their ground colour without a line. `shade()` first rotates the reflection by the turn from the point's up to the camera's (the map's horizon is the camera's; on a small planet a point 30 blocks away is ~10° off, and far ground reflected a green band). Storage: a 2-slot cube-map array, 128² per face, 6 levels (128 … 4, level i filtered for GGX roughness i/5; `env_sample` reads level `roughness × 5` of the read slot, `EnvParams.slot`), group 0 bindings 11–12 of the scene (with the cloud map's sampler; in both `global_bind` and `global_bind_identity`). Baking (`EnvMap::update`, after the frame's global/biome uniforms are written, its own submission, planet mode only): one step per frame — a face of the source cube (`fs_env_bake` in `src/render/shader.wgsl`, the scene's group 0; `EnvMap::src`, 128² with a box mip chain), or one level of the back slot (`fs_env_filter`: 32 Hammersley GGX samples, V = N = R, PDF-chosen source mip against undersampling; level 0 a copy, which first box-mips the source, `fs_env_mip`) — 12 steps (~0.2 s at 60 FPS), then the slots swap (`env_map::Schedule`); the whole map is baked at once at start-up, on a planet switch (`force_reload_all`) and on the first planet frame after space mode (`Renderer::env_reset`). From the cloud shell up the map's sky (baked from the camera) is space, so `shade()` fades to the analytic sky by camera altitude, fully from 1.5× the cloud shell's radius (`env_map::map_weight`, `ENV_FADE_TOP`): above the clouds and at the landing handover the reflection matches the impostors'. `/plastic env off` = the analytic formula. Water still has its own reflection; `fs_water` could read the map via `env_sample` (sharper water reflections would want a finer map). Cost: Lighting unchanged (measured, fullscreen); the bake runs outside the timed passes (a face 16k texels, a level ≤ 6·64²·32 samples: estimated well under 0.1 ms per frame, not measured).

### Weather (`src/weather/mod.rs`, `src/weather/weather.wgsl`, `src/weather/weather_map.wgsl`)
Deterministic weather (spec `docs/superpowers/specs/2026-10-11-weather-design.md`): `src/weather/weather.wgsl` is a function of the direction from the planet centre (planet frame) and the shared clock wrapped at 3600 s, no state — two octaves of value noise (`weather_noise`), its domain turned about the spin axis and a horizontal axis and offset along a closed circle, every rate a whole number of cycles per 3600 s, so it is exactly periodic with the clock; `smoothstep(STORM_LO, STORM_HI)` gives `storm` (about a quarter of the planet over 0.5; a storm passes a point in a few minutes). The map texel is `weather_sample` = (storm, rain history `max(r(t), 0.7·r(t−30), 0.45·r(t−60), 0.2·r(t−90))`, cover history at 0/−60/−120/−180 s, snow share — `|dir.y|` 0.6–0.8): wetness rises with the rain and dries in ~1.5 min, cover lasts twice as long, all derived from past weather, so it is right immediately after a jump or start-up. Type-independent, since every planet shares the cloud field; `WeatherKind::for_planet` gives each planet type a rule applied where the map is read (`weather_surface`; uniforms `BiomeUniform.weather_rule/cover`, `PlanetUniform.weather_rule/cover`): Earth-like and Ocean rain with snow toward the poles, Toxic acid rain (wet everywhere, no snow), Ice snow, Volcanic ash (dark grey), Desert sand-coloured dust (no wetness), Shattered and Cratered none (Shattered: storm clouds only; Cratered has no atmosphere at all). `src/weather/mod.rs` mirrors the WGSL line by line (a test keeps the constants equal; Rust's `f32::fract` differs from WGSL's for negatives, so it uses `x − floor(x)`) for the readout, the camera's storm value and the tests. **The map** (`WeatherMap`, pattern of the cloud map): a 64² `Rgba8Unorm` cube-map array of 3 snapshots `SNAPSHOT_SECS` (5 s) apart, the two around now blended, the next baked ahead, each in one pass (`src/weather/weather_bake.wgsl`); group 0 bindings 13–14 of the scene (both global bind groups) and of the space camera, sampled with the cloud map's sampler (`weather_at`); updated every frame in both modes, before the cloud map. **Clouds:** the cloud bake adds `storm · STORM_COVER` to its raw noise (a regional shift of the threshold, exact because it's applied before it), so storms are closed cloud masses at no draw cost; `atmo_cloud_shade` darkens them toward 40 % of `cloud_dark` with less silver lining; `atmo_cloud_shadow_map` (scene and impostors) reads the cloud map at a coarse level instead of `cloud_coverage_fast`'s own noise, so shadows lie under the visible clouds, deeper under storms (`STORM_SHADOW`); the flare shader has no cloud map and keeps the old noise, its intensity × (1 − storm at the camera). Under storms the fill light drops by up to 30 %, and the sky dome greys and dims by up to 40 % (`Atmosphere.overcast` = `GlobalUniform.weather.x`, `weather::overcast`: the storm over the camera, gone from 0.9× the cloud shell's radius up; 0 on the impostors). **Materials** (`weather_material`, `shade()` and `planet_color`, one map read per pixel): `shelter = smoothstep(0.35, 0.75, ao)` from the ray-traced AO (1 without it, and on the impostors) keeps rain and cover out from under overhangs; wet = wetness × (0.3 on walls … 1 on tops) × shelter → roughness toward 0.05, colour × 0.8, reflection weight toward 0.35; puddles (patches of value noise on flat tops, `rule.w`, about a third of them when soaked) roughness 0.02, reflection 1; cover = cover × upward facing × shelter, against value noise so it grows in patches, replaces colour and roughness (snow 0.9/0.9/0.95 r 0.6, ash 0.12 r 0.9). Console `/weather` (no value: the state at the player), `clear|rain|storm|snow` (forces a state within ~60° of where it was given, fading in over 4 s; rain refused where a type has none, snow is ash on Volcanic), `auto` (fades the force out; `WeatherSettings::tick`, called once a frame by `Renderer::update_sky_maps`, drops it only `FORCE_FORGET_SECS` (194 s) later, once no history sample can still see it, so the wetness and cover it left dry out instead of vanishing; `tick` also rewrites an established force's `start` to a far-past sentinel so it doesn't drop out an hour later through `weather_age`'s wrap; neither changes a baked value, so no rebake)., `on|off` (off: storm 0 everywhere, the old look); a change rebakes both maps (`Renderer::weather_changed`). In space mode only `on|off` work (the player position and loaded type are stale there). A force is a planet-frame direction on the shared map, so it also shows on every other planet (impostors included) in that direction; harmless. Cost: Lighting unchanged (1.76–1.78 ms with `/weather off` and with a storm, 800×600 windowed; fullscreen not measured); the bakes run outside the timed passes.

**Precipitation** (`src/weather/precipitation.rs`, `src/weather/precip.wgsl`; spec `docs/superpowers/specs/2026-10-11-precipitation-design.md`): rain, snow, ash and dust around the camera, realistic look. Stateless: no particle buffer, no compute pass. `Precipitation::update` (every planet frame) picks the kind (`kind_for`: the planet's `WeatherKind`; on `Rain` planets snow where the snow share at the camera > 0.5), the intensity (`weather::precipitation(storm)` at the camera × `altitude_fade`, none from the cloud base up), the instance count (`N_max` × intensity: rain 16000, snow and ash 8000, dust 6000; hashed positions, so more rain adds particles without popping), the wind (`wind_at`: `dir × Y` × `WIND_MAX` 8 u/s × storm, east–west along the fronts' travel, none at the poles) and the particles' offset in the camera's local frame (`frame_at`: up, east around the spin axis, north): fall and wind × dt minus the camera's own movement (a move over 30 units in one frame is a teleport and adds nothing), wrapped into `BOX_SIZE` (40 × 30 × 40), so the rain stays fixed in the world. The **roof grid** (`RoofGrid`, 64 × 64 one-unit cells in the camera's tangent plane at build time): per cell the radius of the column's highest surface, the top of `surface()` (edits included) or the water; rebuilt when the camera is more than 8 units from its origin, on an edit (`edit_generation`) and after a reset (planet switch, space mode); `R32Float` texture. `vs_precip` (appended to the scene shader) places particle `i` at `hash(i) · BOX_SIZE + offset` wrapped around the camera, sways snow and ash, hides it below its roof-grid cell (+0.1) and fades it near the camera and toward the box faces; rain and dust are camera-facing streaks along their velocity (length speed/30; at least 1 px wide, fainter instead), snow and ash soft flakes (0.12 u, at least ~2 px, fainter by area below). `fs_precip` fades against the G-buffer distance (group 3's `d_dist`), lights with the sky's ambient and a little sun × cloud shadow, and outputs premultiplied through `post_process`. Drawn in the lighting pass right after the water (`PrecipGpu::draw`; groups 0, 2, 3 already bound; its own group 1 at bindings 1–2, binding 0 being the scene's `Local`); none with the camera under water, in space mode, with `/weather off` or `/weather particles off`. Cost: Lighting +0.01–0.04 ms in a storm (800×600 windowed; fullscreen not measured). Accepted: rain ends at the first roofed column (block precision); radial motion blur doesn't blur the particles.

**Fog** (`src/weather/fog.rs`, `atmo_air_fog` in `src/render/atmosphere.wgsl`; spec `docs/superpowers/specs/2026-10-12-fog-storms-design.md`): storms and wet dawns thicken the air. Three terms in one `atmo_air_fog` call (shared by `fog()` in `shade()`, `fs_water` and the impostors' `fs_planet`): the **base** exp² fog (unchanged), the **storm** haze with structure and the **ground mist**; the storm and mist optical depths are added to the exp² exponent (`extra`) and the fog colour mixes the sky dome toward the haze tint (× `atmo_ambient_daylight`, × the overcast dimming, so a storm haze is dim at night and under thick cloud) and the mist colour in proportion to each term's share. Maths: `atmo_storm_optical_depth` (peak extinction × `fog_storm_weight(storm)` = smoothstep(`FOG_STORM_LO` 0.25, 1, storm) × structure × height mean × distance) and `atmo_mist_optical_depth` (closed form); `src/weather/fog.rs` mirrors both (`storm_optical_depth`, `mist_optical_depth`, `mist_strength`, `camera_storm_mix`, `mist_region_weight`) and its constants test keeps `CONSTANTS` equal to the WGSL `const`s. **Per type** (`storm_fog(WeatherKind)`, peak extinction per unit at storm 1, visibility ≈ 3 / peak, tint): Dust (desert) 0.07 sand-brown (~40 u), Ash (volcanic) 0.06 near-black, Snow (ice) 0.08 whiteout, AcidRain (toxic) 0.012 yellow-green (~250 u), Rain (earth-like, ocean) 0.004 grey (~750 u, faint), None (shattered) 0; times `/weather fog density`. **Structure:** the density swings by `FOG_STRUCTURE` (0.6) around its mean with value noise (`FOG_STRUCT_SCALE` 0.02, cells ~50 u) tapped along the view ray only within `FOG_STRUCT_MAX_DIST` (300) of the camera, at p - o where o is the wind offset, so the banks drift with the storm (`Renderer::fog_wind`, integrated by `fog::advance_wind` from `precipitation::wind_at`, not time × wind, so gusts do not jump). **Height falloff:** heights are measured above `storm_base` (`GlobalUniform.fog_wind.w`: the radius of the highest natural peak; impostors `impostor::storm_base`) and the haze falls off as exp(-h / `STORM_HEIGHT` 30), exactly 1 on the ground (the mean along a climbing path is closed form), so from above a storm its tau is bounded and the planet from orbit is not a flat disc. **Storm value:** near the ground the mean of the camera's and the shaded point's storm (a surface seen through a storm at either end is hazy), from altitude the shaded point's alone (`camera_storm_mix`, weight exp(-h0 / `STORM_HEIGHT`)); `fog()` takes the point's storm from the weather map. **Mist** (wet types only: Rain and AcidRain; `mist_strength`): a regional field of its own (the weather noise through a turned frame, periodic over the wrap) × a low-sun term (peaks at dawn and dusk, zero at night and by noon), density `MIST_EXTINCTION` 0.02 × exp(-h / `MIST_HEIGHT` 10) above the sea surface (`mist_base`), integrated in closed form along the ray from the camera's mist value only (sampled once, at the camera), and faded with the camera's height by `MIST_REGION_HEIGHT` 150 (`mist_region_weight`), so it is gone from altitude. **Uniforms:** `GlobalUniform.fog` (storm at the camera, peak × setting, mist, mist base), `fog_tint` (rgb), `fog_wind` (xyz offset, w = `storm_base`), filled every frame in `Renderer::render` from `FogParams::at_camera`; impostors: `PlanetUniform.fog_tint` (rgb tint, w = peak × `SpaceRenderer.look.fog_scale`), the storm base in `atmosphere.y`, and `SpaceCameraUniform.fog` (xyz = `SpaceRenderer.fog_wind`, set by the renderer every frame); impostors take the storm from the weather map at the point and get the storm term only, no mist. **Underwater** (`engine_fog`: camera below the water surface radius `screen.z`): no storm or mist, the underwater tint wins. **Precipitation** fades with the same `fog_storm_weight` (`fs_precip`), so streaks and flakes melt into the haze instead of showing through it. Console `/weather fog` (state), `on|off`, `density <0-3>` (× the storm extinction), `mist <0-3>` (× the mist strength) (`FogSettings`, `FOG_USAGE`); `/weather off` turns the fog off with the rest. Cost (windowed default size, desert, `VOXANET_POSE_ALT=5`, `--bench 6`, storm forced, `/film off`): lighting median 0.252 ms with fog on and off (clear sky 0.254), frame median 3.62 / 3.55 / 3.49 ms (on / off / clear), gpu_total 2.40 / 2.37 / 2.33 ms: within noise (geometry differs 0.03-0.07 ms between runs, not the fog's pass). Accepted: the mist is sampled at the camera only (a bank far away is not seen from a mist-free spot); impostors have the storm haze but no ground mist; the sky itself is not fogged, so ridges can stay visible as a skyline in a whiteout; snow storms on Earth-like and Ocean planets (snow share > 0.5 toward the poles) get only the faint rain haze, since the fog follows the planet type, not the precipitation kind.

**Lightning** (`src/weather/lightning.rs`, `src/weather/bolt.rs`, `src/weather/lightning.wgsl`, lightning terms in `src/render/atmosphere.wgsl` / `clouds.wgsl`; plan `docs/superpowers/plans/2026-10-12-lightning.md`): storms flash. Stateless schedule from the shared clock: the planet surface is a cube-face grid of strike cells (n = clamp(round(2R / `CELL_SIZE` 80), 4, 32) per face edge, so cells are ~80 units), each cell-slot jittered per (face, i, j, slot) and seeded per planet; slots are `SLOT_SECS` 1.5 s (3600 / 1.5 divides the clock wrap) and a strike's `LIFE` (0.65 s, main flash plus re-strikes, `envelope`) lies inside one slot, so only the current slot is evaluated. Rate per cell-slot = `RATE_FULL` (0.03, one per ~50 s per cell at storm 1) x type rate (`kind_rate`: Rain/AcidRain 1, Ash 0.4, Dust 0.1, Snow/None 0) x the `/weather lightning rate` setting; gated by `weather::storm` at the site (at least `STORM_MIN` 0.5) and by `/weather off`. `active_strikes` returns the active set sorted strongest first, at most `MAX_STRIKES` 6, within `RANGE` 3000 units of the camera in the voxel frame, `f32::MAX` (the whole planet) for impostors, which skip planets beyond 60 radii. It feeds `Global.flash/strikes` (`GlobalUniform`, `frame_strikes`/`gpu_strikes`), `PlanetUniform.flash/strikes` and `Atmosphere.flash/strikes`. Three visible parts. **Scene flash** (`flash_at`: horizon-aware, so a strike behind the horizon or the curve of a small planet counts less; range `min(FLASH_RANGE 600, 1.2 R)`, a quarter at that distance) is added to the ambient, the sky dome (`LIGHTNING_DOME_GAIN` 0.25) and the water's sky fill (`LIGHTNING_AMBIENT_GAIN` 0.5 at full flash, colour `LIGHTNING_COLOR` (0.55, 0.65, 1.0)), in the voxel frame only; impostors get flash 0. **Cloud glow** (`lightning_cloud_glow` in `atmo_cloud_shade`: a Gaussian of radius `LIGHTNING_GLOW_RADIUS` 0.13 planet radii on the cloud shell around each strike, x `LIGHTNING_CLOUD_GAIN` 2.0; the radius is mirrored in Rust, `CONSTANTS`, tested) shows in the voxel frame and, the only lightning part there, on the impostors from orbit. **Bolts** (`bolt.rs`, `LightningGpu`, `bolt_instances`): additive jagged strips from the cloud shell to the ground, drawn in the lighting pass after the precipitation; none under water, above the cloud shell, in space mode or in the map layout. Console `/weather lightning` (state), `on|off`, `rate <0-3>` (`LightningSettings`, `USAGE`). Cost (windowed default size, earth-like, `VOXANET_POSE_ALT=5`, `VOXANET_POSE_PITCH=-0.1`, `--bench 6`, `/film off`, storm forced; the bench clock is frozen at 0 and a forced storm fades in over ~4 s, so strikes may or may not fall in the window): lighting median 0.403 / 0.401 / 0.389 ms (rate 3 / lightning off / no storm), frame median 4.10 / 4.00 / 4.00 ms, p95 4.97 / 5.21 / 5.60, geometry 1.28 / 1.24 / 1.31, gpu_total 2.76 / 2.69 / 2.73: within noise. Accepted: the env map bakes the flash late (plastic reflections lag it); rain is not lit by the flash; strikes cast no shadows; no thunder; impostors get the cloud glow but no whole-disc flash; bolts exist only in the voxel frame and below the cloud shell.

### Fill light: ground bounce and wrap lighting (`src/render/light.rs`)
The lower half of the hemispheric sky light is the ground's light, `atmo_ground_bounce` (`src/render/atmosphere.wgsl`): `GROUND_COLOR`'s dark floor under the sky's fill light plus sunlit ground in the surface's own (linear) colour × sun × cloud shadow × the sun's elevation at the point × `bounce` — the cheap stand-in for one bounce of global illumination (what lies around a block is mostly its colour), so walls and overhangs pick up a tint instead of a fixed dark brown; top faces, which see only sky, are unchanged. The same ground colour is the plastic reflection below the horizon (`atmo_plastic`'s `ground`). Wrap lighting, `atmo_wrap_diffuse` = (N·L + w)/(1 + w), lets the diffuse sun reach past the terminator (not the GGX highlight). `shade()` and the impostors' `planet_color` use both (`GlobalUniform.light` / `PlanetUniform.light` = (bounce, wrap), `LightSettings::uniform`, `Renderer::light`), so the landing handover keeps the look. Defaults bounce 0.5 (shadowed walls ~9 % brighter, greener on grass), wrap 0 (crisp; 0.3 brightens walls turned from the sun by ~35 %); console `/light [bounce <0-1>|wrap <0-0.5>]`. Cost: a few ALU per pixel.

### Sun shadows: hardware ray tracing or ray marching, no shadow map
The sun is a fixed directional light (`sun_dir` in `Renderer::render`). There is no shadow map. Per frame (`src/render/rt_blur.rs`):
1. `Deferred::downsample` (`cs_gbuf_down`) fills `RtBlur::g_pos` / `g_nrm` (world position + camera distance, normal) at the shadow resolution, capped at `MAX_RT_PIXELS` (1.5 MP).
2. A compute pass computes the sharp shadow term once per texel into `RtBlur::target`, using one of two paths.
3. `src/render/blur.wgsl` softens its edges (separable, depth-aware), and `shade()` upsamples it through bind group 2 (`shadow_at()`: 4 taps weighted by camera-distance match; `GlobalUniform.screen` carries the screen size). Every pipeline using the scene layout must bind group 2.

**Soft shadows** (`src/render/shadow.rs`, spec `docs/superpowers/specs/2026-10-11-soft-shadows-design.md`): the sun is an area light of a fixed, tunable angular radius (default 2.5°; not the real star's, which the compressed solar systems make ~17° on the start planet), so a shadow is sharp where its caster touches the receiver and widens with the distance between them. `cs_shadow` stores the shadow ray's **nearest** hit distance (no `TERMINATE_ON_FIRST_HIT`: +0.18 ms fullscreen, measured; a far first hit softened contact shadows) in the target's third channel; `fs_search_h`/`_v` (`SEARCH_TAPS` 4 per side, within the widest edge possible at the texel's camera distance) average the blocker distances of the shadowed texels around each texel on the same surface — as separable sums (Σ t, count), so a lit texel beside a shadow gets that shadow's distance — and write the edge width `penumbra_width` = min(t, `MAX_BLOCKER` 32)·tan(sun) + `MIN_WIDTH` 0.03 into `RtBlur::widened` (via `search_tmp`); the two blur passes use it per texel (`TAPS` 8 per side, capped at 32 px; `BlurParams.mode` 1). `/shadow off` and the ray-march path (no hit distance) use the fixed `shadow::FIXED_WIDTH` 0.3 and skip the search (`RtBlur::blur(…, soft)`, `set_params(…, None)`). Console `/shadow [on|off|sun <0-10>]`. Cost (fullscreen): nearest hit +0.2 ms in Rays, search +0.35–0.5 ms in Blur. Known limits: the search averages, so a contact edge next to a far blocker's shadow gets a wider edge (each sample capped at `MAX_BLOCKER`); a shadow strip thinner than the search's tap spacing (up to 8 px) can be missed by the lit texels beside it and softens on one side only — inherent to the 4 search taps, not a bug.

The two paths:
- **Hardware ray tracing** (`src/render/hw_rt.rs`, `src/render/rt_hw.wgsl`), the default when the device has `EXPERIMENTAL_RAY_QUERY` (opted in with `ExperimentalFeatures::enabled()`); console `/hw_shadows [true|false]` switches (`Renderer::set_hw_shadows`). Every `ChunkMesh` gets a `blas` (vertex/index buffers need `BLAS_INPUT`); `HwRt::update` rebuilds the TLAS over all loaded chunks each frame; `HwRt::trace` casts one ray per texel. Don't put ray-query code into `src/render/shader.wgsl`: in the big scene shader it made the whole pass ~3× slower even unexecuted.
- **Ray marching** (fallback, `cs_march` in `src/render/shader.wgsl`, `RtBlur::march`): `src/render/rt_shadow.rs` builds a window of solid/air bits per cube face (whole faces up to `WINDOW_SIZE` = 256 columns per face, otherwise windows on the faces turned toward the player) plus 8×8-column max-height tiles; a window's layers run from its lowest column or deepest mined cell (below it reads as solid) up to its highest column or placed block, rebuilt in `Renderer::update_rt_window` when the player moves far, changes face, or a block is edited (`rt_dirty`). `rt_shadow()` walks those cells toward the sun: 3D DDA in block space on short segments (re-linearised for the planet's curvature), bisection across cube-face edges, and adaptive steps that double (up to `RT_MAX_STRIDE`) while a climbing ray passes above the max-height tiles.
- `RtParams`/`FaceWindow` in `src/render/rt_shadow.rs` must match the WGSL structs. The UI bind group uses `rt.enabled = 0` ("lit, don't read the shadow texture"); in hardware mode `update_rt_window` still writes `enabled = 1`.
- The debug overlay's GPU timer (`src/render/gpu_timer.rs`) shows geometry, rays (downsample + shadow compute), blur, lighting and text.

### Coordinates (`src/meshing/gen.rs`, `CoordSystem`)
A `BlockId` is `{face: 0..6, layer, u, v}` on a cube-sphere. `resolution` is the voxel count per face edge. Cube→sphere uses the Nowell mapping (`cube_to_sphere`), and `cubize_point` is its inverse. Layers are radially **exponential**, not linear: `get_layer_radius(layer, res) = (res/2) * exp(K*(layer/(res/2) - 1))` with `K = 0.85`, so voxels keep a roughly cubic shape at every depth. Convert between world positions and blocks only through `CoordSystem` (`pos_to_id`, `get_local_coords`, `get_block_center`, `get_vertex_pos`). Never hand-roll the math.

### Renderer owns streaming and LOD (`src/render/renderer.rs`)
`Renderer` is the largest module. Besides the frame passes (deferred geometry/lighting, shadows, overlays, glyphon text), it also owns world streaming:
- **Small planets are all voxel chunks** (`all_voxel`: up to `ALL_VOXEL_MAX_CHUNKS` = 6·16·16, i.e. radius ≤ 256: moons and small added planets; generated planets are 160–1000, so only the smaller ones are, the rest use the quadtree): `update_view` requires every chunk of the planet (loaded nearest first) and no LOD meshes. Voxel chunks load within ~12 × 64 columns, so near the ground these planets were (nearly) all voxel chunks anyway; streaming them whole means they're meshed during the captured approach (the landing handover waits for `view_covered`), and the descent has no voxel ↔ LOD hand-overs left to dither in (it used to fade in ~600 chunks between the handover and ~40 blocks altitude). They appear without a fade (nothing underneath to cross-fade from). Costs ~20 % frame rate at mid altitude compared to the quadtree; the same at ground level.
- Otherwise (bigger planets, `/system add` up to radius 500) `update_view` walks a quadtree per face (`process_quadtree`, logical size `res.next_power_of_two()`). Nodes split when `node_distance` (camera to the node's centre at sea level; for the node under the camera its altitude above sea level) falls below `split_distance` (`node_radius * lod_factor`, `lod_factor` growing as node size shrinks). Leaf nodes at `CHUNK_SIZE` near the player become full voxel chunks (`ChunkKey` → `chunks`). Coarser nodes become heightfield LOD meshes (`LodKey` → `lod_chunks`).
- **Geomorphing** between LOD levels: every LOD mesh has a second vertex buffer (`LodMorph`, `MeshGen::generate_lod_morph`: its parent level's surface height along each vertex's up, normal and colour; even grid vertices sit on the parent's own, odd ones on the parent's triangles), drawn with the `vs_lod` pipelines (`Deferred::geom_lod_fill`/`geom_lod_wire`). `Renderer::morph_factor` (in `LocalUniform.params.z`) is 1 where a node appears (its parent's `node_distance` at the parent's split distance) and 0 before it can split itself, so LOD levels hand over without a visible change. `ChunkMesh::params` caches the uniform's params, written only when they change. Hardware-traced shadows use the unmorphed LOD shape.
- Mesh generation runs on `std::thread::spawn` workers that get a **cloned `PlanetData`** (cheap: the height map and the edits are both behind `Arc`s) and send `(key, verts, indices)` back over `mpsc` channels (`mesh_tx/rx`, `lod_tx/rx`). Per-frame budgets cap spawns and GPU uploads. `pending_*` sets dedupe in-flight work. Every result is stored, empty ones too (a low-poly chunk one column wide at a face edge, res = 32·n + 1, owns no cells): an empty mesh dropped instead stayed missing and was meshed again every frame, nearest first, starving the queue (Rilo #7 streamed in at a few chunks a second); empty meshes get no BLAS and no draw, and chunk bounds cover the water vertices too (`mesh_bounds`).
- A mesh that is no longer required (voxel chunk or LOD node) is kept alive until every required mesh overlapping its area has loaded (the `uncovered` check in `update_view`), so LOD splits, merges and voxel ↔ LOD hand-overs never leave holes. Removed meshes go to `LodAnimator` (`src/meshing/lod_animation.rs`) to fade out, and new ones fade in (1 s, screen-door dither in `fs_geom`: `dither_discard`; a mesh fading out, `params.y` = 1, keeps the complementary pixels, so a swap whose fades start together covers every pixel exactly once).
- After a block edit, `refresh_neighbors` must be called so the affected chunks get remeshed. After swapping in another planet, call `force_reload_all`: it bumps `Renderer::generation`, and worker results tagged with an older generation are dropped. Without that, a mesh of the previous resolution that was still in flight got stored under a current key and was never rebuilt (a chunk-sized hole into the planet after `]`/`[`).

LOD mesh colours (`MeshGen::lod_sample`, also the near impostor's) imitate the voxel rendering rather than flat block colours: dry land mixes in the block below the top on slopes, terrace step faces (`lod_land_color`), darkened by `LOD_OCCLUSION` for the voxel terrain's AO and shadows; water is `lod_water_color`, fs_water's look from above (floor through a depth-darkening body, sky-lit, blended in display space), with `LOD_WATER_GAIN`/`LOD_WATER_REFLECTION` calibrated against the voxel world at the landing handover (Earth-like, Yellow star). Lava stays the flat shallow colour.

`MeshGen` (`src/meshing/gen.rs`) builds voxel chunk meshes (with AO and skirts), LOD meshes, and debug geometry (player cylinder, collision boxes). `Vertex` is `bytemuck::Pod` and uploads directly. All shading (ray-marched sun shadows, atmosphere/clouds, exp² fog, ACES, dithered transparency) is in `src/render/shader.wgsl`, loaded with `include_str!`. CPU-side uniform structs (`GlobalUniform`, `LocalUniform`) must match its layout.

### Gameplay loop (`src/main.rs`)
`App` implements winit's `ApplicationHandler`; the window and `Game` (renderer, controller, player, planet, console) are created in `resumed`. `Game::tick` runs before every window/device event and on `about_to_wait`: `controller.update_player` (physics), raycast to cursor, `renderer.update_cursor`, `renderer.update_view`; then the event is dispatched. On macOS the surface is tagged Display P3 and `fs_main` converts its output from sRGB to P3 primaries (flag in `sun_dir.w`), otherwise colours show oversaturated. `Physics` (`src/player/physics.rs`) is a custom kinematic solver. Up is `normalize(position)`, orientation uses `Quat::from_rotation_arc`, and collision samples `exists()` with a 5% edge "shave" margin. `Console` (`src/app/cmd.rs`) captures keyboard input while open. Water: `PlanetData::water_depth` gives the feet's depth below the sea surface (None unless the column's sea-level cell holds water, `holds_water`, measured from its lake's or the sea's surface); deeper than `SWIM_DEPTH` (and not flying) `Player::update` hands over to `Player::swim` (`src/player/entity.rs`): half speed along the look direction, buoyancy toward `FLOAT_DEPTH`, drag, Space = up / surface hop, Left Shift = dive. Fly mode (`flying`) has no collision (`Physics::solve_movement` just integrates position), so `Player::update` enforces its own terrain-following floor: hover clearance above the highest terrain sampled ahead along the current horizontal velocity (`fly_terrain_floor`), only ever pushing the player up (`fly_floor_climb`, rate-limited) and clamping an active descent so it can't cross the floor within one tick (`fly_max_descent`) — so Left Shift (fly down) or diving via pitch can't be used to fly through the ground, and flying on over lower terrain keeps the current altitude instead of hugging the ground. Space/Left Shift climb/descend along the planet-relative up vector in fly mode, independent of where the camera looks. In first-person fly mode the flight keys apply (`Controller::flight_input` → `FlightKeys`): A/D roll the camera and the mouse and Q/E turn it about the ship's own axes (`Player::ship_axes`, set by the controller for first-person flight: yaw about the camera's up, pitch about its right, the result split back into rotation/pitch/roll by `landing::camera_angles`, so pitch can pass ±90°; walking, swimming and third person keep yaw about the planet's up and the ±1.5 pitch clamp, `turn_on_the_horizon`) (`Player::cam_roll`, applied after the pitch in `get_view_matrix`; below the clouds, released A/D let the roll level itself with the horizon, arcade style — `smoothing::roll_level_rate`, `ROLL_LEVEL_GAIN`, paused while the glide pulls over the top; above them, and in space flight, it stays rolled) and Q/E turn through eased rates (`Player::roll_rate`/`turn_rate`, ramping up in 0.3 s and coasting to a stop in 0.3 s after release), with no sideways movement. Glide assist (`landing::glide_assist`, state `Player::glide`/`glide_armed`): a descent coming down below the glide ceiling (`landing::glide_ceiling`: twice the cloud layer's altitude; armed while above it) is brought onto a line at the take-off height (`takeoff_target_layer`'s radius, fixed when it engages) and then follows the planet's curve there. It replaced a time-to-impact dive assist that, with fly speed proportional to altitude, was engaged at any height and pulled out into a straight line that left small planets again. The climb angle is steered toward `glide_path_angle` (the remaining height in `GLIDE_TAU` 3 s at the current speed, at most 75° down / 20° up), velocity and view turned together (a world rotation; `landing::camera_angles` splits the view back into rotation/pitch/roll without the pitch clamp, so it can pass through a vertical dive), at `GLIDE_SOFT_RATE` (0.6 rad/s) — harder, up to `GLIDE_HARD_RATE`, only when levelling out wouldn't fit into `GLIDE_ROOM` (70 %) of the remaining height (steep dives into small planets: fly speed ∝ altitude makes them fast relative to their size). While pulling out it brakes the fly speed toward `GLIDE_BRAKE` (0.5/s) × the remaining height (`GlidePull::max_speed`, never below `move_speed`), so the curve stays soft and long. A steep pull-out goes toward the ship's own up (the camera's, so it follows the roll): over the top unless the flight line hits the lower `GLIDE_UNDER_SHARE` (30 %) of the planet's diameter along the ship's up, then under; the side is kept until the pull-out is done (`GlidePull::axis`), so upside down in a steep dive it pulls a split-S and comes out upright. The player takes over by pitching with the mouse (screen up/down, `GLIDE_CANCEL_MOUSE`), Space/Shift or F (landing/take-off); it engages again only after climbing back above the ceiling. Banked turn: while rolled and flying forward below the clouds (none in space) the heading turns toward the lowered side (`BANK_TURN_RATE` × sin(roll) × forward share of cruise speed). Fly-mode velocity eases toward its target (`smoothing::ease_toward`, `FLIGHT_EASE_SECONDS`). On foot, swimming and in third person A/D strafe and Q/E turn directly as before. Walking and swimming are level; an F landing ignores the flight keys and eases the roll level (`LANDING_ROLL_LEVEL_RATE`), the take-off climb ignores them. F (first person, planet mode; `src/main.rs`, decision in `landing::f_action`) lands while flying — an automatic descent along local down (`landing_descent_speed`: fast high up, easing in near the ground; WASD still steers; F again cancels) that switches to walking, or swimming in water, on touchdown (`Player::update` returns true, `Controller::update_player` turns fly mode off) — and is refused over lava (`landing::over_damaging_liquid`); while walking or swimming it takes off: fly mode plus an automatic climb along local up (`Player::taking_off`, the landing descent mirrored: `landing::takeoff_climb_speed`, easing in without overshooting; WASD steers; F during it stops and hovers, `FAction::StopTakeOff`) to `landing::takeoff_target_layer` — `TAKEOFF_RELIEF_SHARE` (30 %) of the planet's relief (highest natural peak above sea level) above the ground (or the water surface when swimming), at least `TAKEOFF_MIN_CLEARANCE` (3) layers, and not above the highest peak, so bigger planets climb higher and canyons stay flyable. Its messages go to the HUD's timed status line (`Renderer::show_status`, `STATUS_SECONDS`), since the console is only drawn while open. Liftoff hands space flight the player's velocity (`landing::liftoff_flight`), so a climb doesn't stall at the handover.

Note: `update_player` runs exactly once per tick; movement and turning speeds are per second (Q/E turn at `TURN_SPEED` in `src/player/controller.rs`).
