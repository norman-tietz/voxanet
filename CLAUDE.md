# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

voxanet is a single-binary Rust voxel engine that renders an explorable spherical planet with wgpu (30) / winit (0.30), glyphon for text, glam for math. There is no library crate and no CI config.

## Commands

```sh
cargo run --release   # debug builds are very slow for terrain/mesh generation
cargo build
cargo check
cargo clippy
cargo test            # 25 unit tests, inline #[cfg(test)] modules in biome.rs, common.rs, entity.rs, gen.rs, material.rs
```

One-time per clone: `git config core.hooksPath .githooks` enables the pre-commit hook (`.githooks/pre-commit`), which `rustfmt`s staged `.rs` files and re-stages them, then runs `cargo clippy` as advisory output (printed, never blocks the commit — the tree has pre-existing warnings and clippy's suggestions aren't always safe to apply blindly). Line endings are LF-normalized via `.gitattributes`; `rustfmt.toml` just pins `edition = "2021"` so standalone `rustfmt` (not `cargo fmt`) picks it up. Nothing here has been run across the whole codebase yet — `cargo fmt` on every file would be a ~10,900-line diff against the existing hand-tuned dense style (very long single-line struct/pipeline literals throughout), so formatting is applied incrementally, only to files a commit actually touches.

## Architecture

### Data model: heightmap + sparse edit diffs
The planet is not stored as a voxel array. `PlanetData` (`src/common.rs`) holds:
- `terrain: PlanetTerrain` (`src/noise.rs`): a precomputed per-column height map indexed by `(face, u, v)`, generated once per resolution (in parallel with rayon). `TerrainShape` builds it from continent noise (ocean vs land around a sea level at layer `res/2`), hills, and ridged mountain noise inside low-frequency mountain zones; overall relief scales with `3·sqrt(res/2)`, capped at 20% of the radius (layers stay ~1 unit thick, so small planets need proportionally less relief). Seeded: `PlanetTerrain::new(resolution, seed)`; `PlanetData::seed` records the seed it was baked with (the galaxy planet's `noise_seed`; `noise::HOME_SEED` = 42 is only the default for `PlanetData::new`, used by tests).
- `chunks: HashMap<ChunkKey, ChunkMods>`: only the player's edits per 32×32 column chunk (`CHUNK_SIZE`): `placed: HashMap<BlockId, BlockType>` and `mined: HashSet<BlockId>`.

`PlanetData::exists(id)` is the single source of truth for solidity: placed → true, mined → false, otherwise `layer <= height`. Meshing, physics, and raycasting all go through it. Layers below 6 are an unbreakable core (`remove_block`).

Block types live in `src/material.rs`. Natural blocks have no stored type: `material::natural_type` derives it from the column's height within the planet's height range (`PlanetTerrain::height_range`), the slope to neighbouring columns and smooth per-column jitter (sand on beaches and the sea floor, stone on steep steps and from 45% of the peak height above sea level, snow from 62%, dirt then stone below the surface). `PlanetData::block_type(id)` combines that with edits; voxel and LOD meshes both use it, so they agree.

### Frame structure: deferred shading (`src/deferred.rs`)
`Renderer::render` draws the scene geometry once per frame:
0. **Galaxy backdrop** (`GalaxyRenderer::render`, submitted on its own before the frame's encoder): the stars (and on a galaxy planet the star and the other planets) behind everything, from the planet camera's pose; it uses `Deferred::depth`, which the geometry pass clears again. See "Atmosphere and clouds".
1. **Geometry pass** (`fs_geom`, full screen resolution): vertex colour (`Rgba8Unorm`), normal (`Rgb10a2Unorm`, `n * 0.5 + 0.5`), camera distance (`R32Float`, 0 = sky) and depth. Chunks, LOD meshes, fading chunks and the third-person player are drawn here; fading chunks dither (discard) as before.
2. **Shadows** (below): `cs_gbuf_down` derives the shadow-resolution G-buffer from it, then one compute invocation per shadow texel, then the blur.
3. **Lighting pass** (`vs_full` + `fs_light`): one full-screen triangle; `shade()` in `shader.wgsl` (lighting, fog, ACES, P3 output) runs once per pixel. Sky pixels (and distant terrain under cloud cover) get `sky_gradient()` + `clouds()` instead of a discard. The lighting pass **loads** the swapchain (the backdrop) instead of clearing it, and `fs_light` outputs premultiplied colour with the sky's opacity as alpha (`PREMULTIPLIED_ALPHA_BLENDING`): terrain is opaque, the sky only where the atmosphere is thick and sunlit.
4. **Water** (`fs_water`, same pass, alpha-blended, depth-tested, no depth write): the per-chunk `ChunkMesh::water` meshes (`MeshGen::build_water`: one quad at the top of layer `sea_level` over every column whose *natural* height is below it; edits don't change the water; swimming uses the same rule, see Gameplay loop). Opacity and colour (turquoise → deep blue) come from the water depth along the view ray, using the G-buffer distance of the sea floor behind the surface. The mesh stays flat: ripples only tilt the shading normal (`water_waves`: six travelling sine waves along fixed world directions, so no seams at cube faces, each fading out with distance before it aliases), and shore foam comes from the vertical water depth (`FOAM_DEPTH`; a surf line plus bands running toward the shore). Time is `GlobalUniform.screen.w` (seconds, wrapped at 3600). Caustics are in `shade()` (so in `fs_light` and `fs_main`): sunlit surfaces below the sea radius get their direct sunlight scaled by `caustics()`, the light density `1/|1 + depth·curvature·CAUSTIC_FOCUS|` of six ripples (`ripple_curvature`, 0.8–1.9 blocks, separate from the surface waves; directions spread evenly over a hemisphere, curvature measured within the local sea surface, lookup point warped by a slow large-scale distortion against visible tiling) at the point where the sun ray entered the water. They don't know about columns, so a mined hole inland that reaches below sea level gets caustics too. Keep the wave sums unrolled with constant unit directions: a loop over constant arrays was ~3× as expensive. Distant oceans are part of the LOD meshes instead (clamped to sea level, `material::WATER_COLOR`, opaque). `GlobalUniform.screen.z` is the sea surface radius, `screen.w` the animation time; `fog()` tints everything when the camera is below it. Chunk bounds include the water vertices. Water's sky-direction fresnel reflection also calls `clouds()`, so cloud shapes show up reflected on the surface.

### Atmosphere and clouds (`shader.wgsl`, no geometry)
The atmosphere maths lives in `src/atmosphere.wgsl` (sky gradient, limb, sky opacity, clouds, cloud shadow, air fog, ACES/gamma), parameterised by an `Atmosphere` (planet radius and colours) and prepended to both `shader.wgsl` (renderer.rs `SCENE_SHADER`) and `galaxy.wgsl` (galaxy_render.rs `GALAXY_SHADER`); the engine's `sky_gradient`/`clouds`/`cloud_shadow`/`fog`/`post_process` are thin wrappers feeding it the globals. Both combined shaders are validated with naga in `cargo test` (`scene_shader_is_valid_wgsl`, `galaxy_shader_is_valid_wgsl`). Air fog counts only the stretch of the view ray inside the atmosphere (`atmo_fog_distance`, sphere at the limb scale): unchanged on the ground, but from orbit the empty space in between adds no haze, so planets don't wash out into flat sky-coloured discs from a few radii out. `atmo_sky_gradient` = `atmo_sky_dome` + `atmo_sun_disc`; the impostors' atmosphere shell uses the dome only, since the galaxy draws the star itself (with the planet-to-star `L`, the engine's disc would be a second sun beside it). A thin cloud shell at `CLOUD_ALT × planet radius` and a stylised sky gradient are both computed procedurally, with no extra mesh or render pass: `sphere_hit()` finds where a ray crosses the shell, `cloud_shade()` raymarches a short span around that point (scaled by `1 / |ray·up|`, so grazing/horizon rays cross far more of the shell and look thicker, same as real atmosphere), and `sky_gradient()` gives a blue-dome-to-black-space falloff plus a limb glow when the planet is viewed from outside its atmosphere. Three call sites share this: `fs_light`'s sky branch, `fog()` (so horizon fog matches the sky in that direction instead of a flat colour), and `fs_water`'s reflection. `cloud_shadow()` (one cheap unwarped noise sample, no raymarch) dims direct sunlight under cloud cover in both `shade()` and `fs_water`. Cloud/sky shape noise is in direction-space (`fbm_clouds`, a domain-warped value-noise FBM, same no-seams reasoning as `ripple_curvature`), not world-position space, so it doesn't depend on the player's distance from the planet centre — which is why these functions read `global.camera_pos.w` (set to `planet.resolution / 2` every frame in `Renderer::render`) rather than `rt.resolution`: the latter is zeroed when hardware ray tracing is active (`RtParams::zeroed()` in the hw-shadows branch), since the ray-march windows aren't built in that mode. The sky is also **partly transparent** over the galaxy backdrop (milestone 2 of the galaxy landing): `Renderer::render` first draws the galaxy behind the voxel world (`galaxy_render::Backdrop`: the starfield, the star and every other planet, from the planet camera's exact pose, `Controller::camera_pose`/`fov_y`, converted into galaxy space), and `fs_light` is alpha-blended over it (`Deferred::light_pipeline`, lighting pass loads instead of clearing). `sky_opacity()` = `smoothstep(SKY_SPACE_LIMB, SKY_OPAQUE_LIMB, atmosphere_limb())` × daylight at the ray's closest point to the planet (`smoothstep(SKY_NIGHT_ELEVATION, SKY_DAY_ELEVATION, sun elevation)`). `atmosphere_limb()` is the atmosphere-thickness term `sky_gradient` already used, but it is only ~0.7–0.9 for a camera standing on terrain, so it goes through the smoothstep rather than being the opacity directly (otherwise stars show through the daytime sky): fully opaque up to ~0.3 planet radii of altitude, fully transparent from ~1.1. `shade_pixel` carries premultiplied colour + coverage through cloud compositing and motion blur, and `fs_light` applies `post_process` to the premultiplied colour and blends with `PREMULTIPLIED_ALPHA_BLENDING`, so a sky pixel lands as `post(sky × a) + backdrop × (1 − a)` — the same `post(sky × a)` that `fog()` fades distant terrain toward (un-premultiplying first made fogged terrain brighter than the sky beside it in the semi-transparent band). Clouds dim to `CLOUD_NIGHT_BRIGHTNESS` on the night side (`cloud_shade`), otherwise they'd glow grey against the black night sky. `fog()` and `fs_water`'s reflection use `sky_over_black()` (sky × opacity), so at night they fade toward dark like the sky instead of toward blue. The engine's own sun disc fades with the opacity, so above the atmosphere the galaxy's star is what's seen. Night skies are therefore dark and starry, with the galaxy's star and other planets in them.

### Planet types (biomes) (`src/biome.rs`, `src/material.rs`, `src/renderer.rs`, `src/entity.rs`)
The planet type (Earth-like, Volcanic, or Ice) is stored in `PlanetData::planet_type` and set when a galaxy planet is baked (`GalaxyPlanet::bake` → `switch_planet_type()`). Each `PlanetType` has a `PlanetTypeDef` (`src/biome.rs`) defining its `Palette` (peak, rock, beach, ground, subsurface block types), optional `LiquidDef` (shallow/deep colour, behaviour, damaging flag), and `AtmosphereDef` (sky/cloud colours). `material::surface_type()` and `material::natural_type()` take the palette as a parameter, so material assignment depends on the active type. On liquid-less planets (Ice), `PlanetData::effective_height()` returns `height.max(sea_level)` instead of just `height`, making the terrain solid all the way up to sea level where there is no ocean mesh to draw; `exists()`, `natural_type()` and `rt_shadow.rs`'s `fill_face()` all call it, so solidity for meshing, physics, raycasting and shadowing agree. `BiomeUniform` (`src/renderer.rs`) captures the liquid and atmosphere colours from the active planet's `PlanetTypeDef`; it's recomputed and written fresh every frame in `Renderer::render` (`BiomeUniform::from_def()`), the same pattern `GlobalUniform` already uses — cheap, no change-tracking needed. `shade()` in `shader.wgsl` reads it for terrain lighting (sky gradient, clouds, ambient); `fs_water` reads it to colour the water (or lava on Volcanic) and adds emissive glow to glowing liquids (liquid_shallow.w = 1.0 for `LiquidBehavior::Glowing`). The health system (`src/entity.rs`) damages the player at `DAMAGE_RATE` (20 HP/s) when submerged in damaging liquid beyond `SWIM_DEPTH` (0.5 blocks); the Volcanic planet's lava is damaging, Earth-like's water is not, and Ice has no liquid. Outside damaging liquid, health regenerates at `REGEN_RATE` (5 HP/s); death respawns at the spawn point. The HP readout (`HP: x/x`) is drawn in the top-right overlay, always visible (not gated on debug mode).
5. **Forward overlays** in the same pass, depth-tested against the G-buffer depth: collision lines, cursor box (`fs_main`, which also calls `shade()`), crosshair, console; then text.

World positions are reconstructed from the camera distance and a camera ray basis (`GlobalUniform.ray_dirs`, built in f64 by `Renderer::ray_dirs` in homogeneous form so the per-pixel interpolation is exact). Don't use an f32 inverse view-projection for this: with near 0.1 / far 20000 it was off by ~0.5 units at 500 units, which made hardware rays self-shadow distant surfaces.

### Galaxy mode (foundation) (`src/galaxy.rs`, `src/galaxy_render.rs`, `src/icosphere.rs`)
A separate, deliberately minimal deep-space mode: a seeded single-star solar system of placeholder planets the player can free-fly through, entirely disconnected from the planet-surface engine above. `Galaxy::generate(seed)` (`src/galaxy.rs`) builds a fixed `Star` plus `PLANET_COUNT` (7) `GalaxyPlanet`s with no true randomness anywhere — `orbit_radius` grows geometrically from `INNER_ORBIT_RADIUS` by `ORBIT_RADIUS_GROWTH` per planet, `orbit_speed` follows a Kepler-like `1/sqrt(orbit_radius)` falloff (`orbit_speed_for`, tuned off `INNER_ORBIT_PERIOD_SECS`), `orbit_phase` spreads planets evenly around the circle, and `planet_radius_for` derives a size in `[MIN_PLANET_RADIUS, MAX_PLANET_RADIUS]` from a bit-mixing hash of `(seed, index)` — so a given seed always reproduces the same system (see the `generate_is_deterministic_for_a_fixed_seed` / `generate_is_different_for_a_different_seed` tests). `GalaxyPlanet::position_at(t)` places each planet on a circle in the XZ plane at a given time `t`; each cycles through `PlanetType::ALL` (`src/biome.rs`), so planet colour reuses the same per-type palette as the main planet-surface engine (`palette.ground.color()`) rather than inventing a second colour table. `GalaxyFlight` (also `src/galaxy.rs`) is a separate, simpler kinematic body from `Physics`/`Player`: no gravity, no collision, no terrain-following floor, just mouse-look (`rotation`) and accelerate-toward-target-velocity flight (`compose_fly_direction`, `accelerate_toward`) at `GALAXY_CRUISE_SPEED`/`GALAXY_BOOST_SPEED`.

`Renderer::render_galaxy` (`src/renderer.rs`) delegates every frame to `GalaxyRenderer::render` (`src/galaxy_render.rs`), a fully separate forward-rendering pipeline (own shader, `galaxy.wgsl`; own camera/body uniforms; no G-buffer, no shadows, no atmosphere/fog) — deliberately, so sub-project #2 (below) could replace the placeholder planet bodies with real terrain-shaped impostors without first unwinding a shared pass. It does reuse two things from the planet-mode pipeline: the depth texture (`Deferred::depth`, `deferred::DEPTH_FORMAT`) and the swapchain/surface itself; everything else (shader code, camera/body uniforms, G-buffer, shadows, atmosphere) is separate. It draws a procedural starfield background (full-screen triangle), then one instanced draw of a shared icosphere mesh (`src/icosphere::generate`, flat-shaded, unlit except for a fixed `light_dir` per body) per star/planet — this instanced path is still exactly how the star renders today; sub-project #2 (below) gave planets a second, parallel path instead of changing this one. Positions use a **floating origin**: `Galaxy`/`GalaxyPlanet` store world positions in `f64` (`DVec3`), and every body's GPU offset is computed as `(body_pos - flight.position)` in `f64` before narrowing to `f32` (`galaxy_render.rs`'s `render`) — so the camera is always effectively at the origin for rendering, and the view matrix itself is rotation-only (`Mat4::from_quat(flight.rotation).inverse()`, no translation). This avoids the f32 precision loss that would otherwise show up at the system's scale (orbits run out to tens of thousands of units, further than where the main planet engine's own f32-precision note above starts to matter).

There is no separate home planet: every planet is a galaxy planet. The game starts on galaxy planet #1, or on the first planet of the `--biome` type (`Galaxy::start_planet_index`), baked synchronously at start-up (`bake_planet` + `install_world`, the same path a capture's background bake takes) and standing at local noon (`noon_spawn`). `Game::loaded_world` is the index of the galaxy planet the voxel engine holds — always one. Debug commands (`src/cmd.rs` → `GalaxyRequest`, applied in `src/main.rs`): `/galaxy home` respawns on the start planet (`Game::start_planet`) at noon from anywhere, `/galaxy goto <n> <radii>` jumps into a planet's orbit, `/galaxy add <type> <radius>` appends a planet of that type and radius (20–500) on the next orbit outward (`Galaxy::add_planet`, at most `MAX_PLANETS` = 15). You leave and arrive only by flying. Landing and liftoff are seamless (milestone 4, `src/landing.rs`): captured galaxy flight hands over to the voxel engine below `LAND_HANDOVER_RADII` (3) from the planet's centre once the voxel world is ready (`loaded_world == i` and `Renderer::view_covered()`), arriving in fly mode at the same eye position and view direction (`player_pose_from_flight`; pitch clamped to the planet camera's 1.5 rad); above `LIFTOFF_HANDOVER_RADII` (3.5) the voxel engine hands back to captured galaxy flight (`flight_pose_from_player`). Galaxy mode renders with the first-person planet camera's 80° field of view (`FOV_Y_RADIANS`), so the view doesn't zoom at the handover. Until the voxel world is ready, captured flight is kept above `MIN_CAPTURED_RADII` (2) so it can't sink into the impostor. On galaxy planets fly speed scales with altitude (`landing::fly_speed`, `Player::handover_altitude`) up to galaxy flight's cruise/boost speed at the handover altitude, so speed doesn't jump either.

Planet frame and sun (`src/galaxy.rs`): `GalaxyPlanet::to_planet_frame`/`from_planet_frame` (and the `rotation_*` variants) convert between galaxy space and a planet's own frame — origin at its centre, spinning about +Y by `spin_angle(t) = t * (TAU / day_length_secs + orbit_speed)`. The orbit term is deliberate: it makes the solar day exactly the planet type's `day_length_secs`. `sun_dir_in_planet_frame` is the real star's direction in that frame; the game passes it to `Renderer::render` (always the real star). It uses the one shared game clock, `Game::clock`.

Captured flight (milestone 3 of the landing): galaxy flight lives in a `FlightFrame` (`galaxy.rs`): `Free` (galaxy space) or `Captured(i)` (planet *i*'s frame). `next_flight_frame` captures within `CAPTURE_RADII` (10) planet radii and releases beyond `RELEASE_RADII` (11) — hysteresis, so hovering at the boundary can't flip-flop; `GalaxyFlight::change_frame` converts position, orientation and velocity so nothing visibly jumps (velocity is only rotated — the player starts co-moving with the planet). While captured, `level_roll` eases roll level with the planet's horizon at `ROLL_LEVEL_RATE`, `GalaxyFlight::update` turns (mouse yaw) and climbs/descends (Space/Shift) about the local radial up instead of the planet's spin axis (`up` parameter: `+Y` in free flight), galaxy mode renders from `GalaxyCamera::from_flight_in_frame`, and every planet impostor is rotated by `GalaxyPlanet::orientation(t)` (its spin), so a captured view sees the planet hold still while the sky turns. Capture also starts a background bake (`main.rs`'s `start_bake`: `GalaxyPlanet::bake()` plus `galaxy_terrain::near_impostor_mesh`); a finished bake is installed unless the player has since gone home, landed or been captured by another planet (`bake_still_wanted`; merely leaving orbit again keeps it, so re-capturing the same planet doesn't re-bake) — it becomes the voxel engine's `planet` (`loaded_world = Galaxy(i)`), the engine streams from the flight's planet-frame position every tick (`Renderer::update_view`), `Renderer::view_covered()` reports when no required mesh is missing, and the planet's impostor becomes the near impostor (`GalaxyRenderer::set_near_impostor`: the engine's own `generate_lod_mesh` for the six whole cube faces, so shape and colours are exactly what the voxel engine shows from orbit). The galaxy planet pipeline draws without back-face culling, like the engine's geometry pass: LOD mesh winding isn't consistent, and culling punched holes into the near impostor at cube-face corners and seams. `/galaxy goto <n> <radii>` (permanent debug command) drops the player captured by planet *n*, over its day side at `radii` × radius from its centre.

The console panel and its text don't render in galaxy mode, so the `/galaxy` confirmation messages are also `println!`'d to stdout as a cheap substitute; the commands still work, just typed blind with no on-screen console to see them in. The only galaxy-mode UI is a deliberately small HUD (`Renderer::render_galaxy_overlay`, glyphon text drawn in its own pass over the finished galaxy frame, no extra pipeline): the same `FPS: N` readout as planet mode (`Renderer::update_fps` is shared by both render paths, so the counter keeps updating across a mode switch), the same white screenshot flash (`Renderer::update_flash`/`draw_flash`, also shared: the flash starts the frame after a capture, so it's never in the PNG), and a compass strip across the top — a tick bar covering ±90° around the view direction with one label per body (`#<orbit number> <type> <distance to surface>`, e.g. `#3 Ice 3.2k`, in the type's ground colour). Bearings come from `galaxy::compass_bearing` (camera-relative yaw/pitch, so they follow mouse-look); bodies outside the strip pin to its edge with `<`/`>`, `^`/`v` mark targets more than 20° above/below, distances use `galaxy::format_distance`, and labels that would overlap stack into rows. From the default entry point everything is nearly straight ahead, so all eight labels stack into one column there — expected, not a bug.

### Galaxy terrain impostors (sub-project #2) (`src/galaxy_terrain.rs`, `src/galaxy_render.rs`, `src/galaxy.wgsl`)
Builds on the galaxy-foundation section above: planets are no longer flat-shaded placeholder spheres, they're meshes displaced by the same noise the player's actual planet uses — without paying for a full `PlanetData`/heightmap per planet, which would defeat sub-project #1's "many planets, bounded memory" design. `GalaxyPlanet` (`src/galaxy.rs`) carries a `noise_seed: u32` (`noise_seed_for(seed, index)`, a bit-mixing hash independent of `planet_radius_for`'s hash so a planet's size and its terrain shape don't correlate); without a per-planet seed every planet would sample the same noise field and look identical apart from radius and palette. `src/galaxy_terrain.rs`'s `generate_planet_mesh(planet, subdivision)` builds on an `src/icosphere.rs` unit sphere: it constructs a `TerrainShape::new((planet.radius * 2.0) as u32)` and `NoiseGenerator::new(planet.noise_seed)` — both now `pub(crate)` (previously private to `src/noise.rs`, the single-planet engine's own module) — and calls `shape.height(&generator, dir)` directly per vertex, with no baked `PlanetTerrain` heightmap in between. Per-vertex colour is a simplified, slope-free height-banded rule (`ROCK_LINE`/`SNOW_LINE` fractions of the planet's own peak relief, `shape_relief()`) rather than `material::natural_type()`, which needs neighbour-slope data that's meaningless on this sparse, widely-spaced mesh; underwater vertices (height < 0) take the active `PlanetTypeDef`'s liquid colour (or the beach colour on liquid-less planets). Displacement is clamped to sea level on every planet type (see the far-impostor note below).

The far (noise) impostor matches the voxel engine's terrain shape: radius `voxel_resolution() / 2` and `TerrainShape::new(voxel_resolution())` (the same rounded resolution `GalaxyPlanet::bake()` uses), heights through the engine's exponential layers (`CoordSystem::get_layer_radius_f`), and oceans/liquid-less basins flattened to sea level on every planet type like the engine's distant LOD meshes; rock/snow bands at material.rs's 45%/62%.

Rendering splits into two paths in `GalaxyRenderer` (`src/galaxy_render.rs`): the star still goes through the original instanced-icosphere `body_pipeline`/`body_buf` storage buffer (unchanged, see above) — it shares one unit-sphere vertex buffer across all instances, varying only a per-instance transform/colour via the storage buffer, which doesn't work once vertex position/colour/normal all vary per planet. Planets get their own `planet_pipeline`, one real vertex/index buffer per `(planet index, subdivision)` in `planet_meshes` (built lazily by `ensure_planet_mesh`, cached for the process lifetime — a planet's mesh is regenerated once per subdivision level it's ever been seen at, not every frame), and a **dynamic-offset uniform buffer** (`planet_uniform_buf`, `has_dynamic_offset: true`, stride rounded up to `min_uniform_buffer_offset_alignment`) carrying each planet's camera-relative offset, light direction and atmosphere colour, one aligned slot per planet. Every slot is written before the render pass begins: `render()` loops over `planet_uniforms` calling `queue.write_buffer` first, then opens the pass and does a second loop that only calls `set_bind_group`/`draw_indexed` with a different offset into that already-fully-written buffer per planet — not per-draw `write_buffer` calls interleaved with the draws. `queue.write_buffer` takes effect relative to the *queue's* execution order, not to when the encoder recording the pass is later submitted; writing a per-planet uniform and immediately drawing with it, repeated inside one not-yet-submitted render pass, would mean every draw ends up reading only the *last* write by the time the encoder is actually submitted (same hazard the star's body-storage-buffer path was already built to avoid).

`GalaxyRenderer::render` draws from a `GalaxyCamera` (galaxy-space position, orientation, vertical field of view: `from_flight` in galaxy mode, `on_galaxy_planet` for the planet-mode backdrop) and a `GalaxyContent` (`Everything`, `AllButPlanet(i)` — the planet the voxel engine is drawing). Bodies farther than `FAR_FIT_DISTANCE` (0.9 × the 200,000-unit far plane) are drawn pulled in along their direction and shrunk by the same factor (`fit_within_far_plane`; for planets the scale rides in `GalaxyPlanetUniform.light_dir.w` and the shader undoes it for its planet-frame lighting), so they keep their apparent size: `/galaxy add` puts planets on orbits far past the far plane, and from out there the star and the inner system are farther still.

LOD is distance-over-radius, re-evaluated every frame per planet (`subdivision_for_distance` in `galaxy_render.rs`): coarsest icosphere subdivision 2 beyond `LOD_MEDIUM_DISTANCE_MULTIPLIER` (13×) the planet's own radius, subdivision 4 between that and `LOD_NEAR_DISTANCE_MULTIPLIER` (6×) radius, subdivision 5 inside 6×radius — thresholds scale with each planet's own radius (not a fixed world-space distance), so a big and a small planet switch tiers at the same apparent angular size. Since planet radii here run 40–250 (`MIN_PLANET_RADIUS`/`MAX_PLANET_RADIUS`, `src/galaxy.rs`), that's roughly 240–1500 units for the near-tier threshold (6×radius) and 520–3250 for the medium-tier threshold (13×radius). Crossing a tier just picks a different cached `(index, subdivision)` mesh — there's no fade/animation between tiers like the main engine's `LodAnimator`.

Impostors are lit like the voxel engine (milestone 5 of the landing): `fs_planet` shades in the planet's own frame (`planet_frame_camera`/`planet_frame_light`) with the engine's `shade()` terms minus ray-traced shadows, caustics and grain — linear albedo, `SUN_COLOR`, sky ambient, rim, cloud shadow, air fog, clouds in front of the surface — and ACES/gamma, all from atmosphere.wgsl with the planet type's `AtmosphereDef` colours (`GalaxyPlanetUniform`). A per-planet atmosphere shell (`vs_atmosphere`/`fs_atmosphere`, back faces of the unit icosphere at `ATMOSPHERE_SHELL_RADII` = 2.3, depth-tested behind the planets, premultiplied blend) draws the sky the engine would show along rays that miss the planet: limb glow and clouds beyond the limb. Cloud time is `GalaxyCameraUniform.screen.z` (shared clock mod 3600, like the engine), so clouds sit in the same places on both sides of the landing handover. Lava's emissive glow (the engine's water pass) is not modelled on impostors.

This milestone was verified manually (screenshots, no automated visual test) by temporarily anchoring the galaxy entry point near a planet instead of the default far-away vantage — see this plan's task-5 report for exact screenshots and findings. Only the near tier (subdivision 5, 900 units) and coarse tier (subdivision 2, 5000 units) were previewed via debug-repositioning; the medium tier (subdivision 4) was not independently visually captured, only covered by the existing `subdivision_for_distance` unit tests.

### Sun shadows: hardware ray tracing or ray marching, no shadow map
The sun is a fixed directional light (`sun_dir` in `Renderer::render`). There is no shadow map. Per frame (`src/rt_blur.rs`):
1. `Deferred::downsample` (`cs_gbuf_down`) fills `RtBlur::g_pos` / `g_nrm` (world position + camera distance, normal) at the shadow resolution, capped at `MAX_RT_PIXELS` (1.5 MP).
2. A compute pass computes the sharp shadow term once per texel into `RtBlur::target`, using one of two paths.
3. `blur.wgsl` blurs it (separable, depth-aware, `PENUMBRA_WIDTH`), and `shade()` upsamples it through bind group 2 (`shadow_at()`: 4 taps weighted by camera-distance match; `GlobalUniform.screen` carries the screen size). Every pipeline using the scene layout must bind group 2.

The two paths:
- **Hardware ray tracing** (`src/hw_rt.rs`, `src/rt_hw.wgsl`), the default when the device has `EXPERIMENTAL_RAY_QUERY` (opted in with `ExperimentalFeatures::enabled()`); console `/hw_shadows set true|false` switches (`Renderer::set_hw_shadows`). Every `ChunkMesh` gets a `blas` (vertex/index buffers need `BLAS_INPUT`); `HwRt::update` rebuilds the TLAS over all loaded chunks each frame; `HwRt::trace` casts one ray per texel. Don't put ray-query code into `shader.wgsl`: in the big scene shader it made the whole pass ~3× slower even unexecuted.
- **Ray marching** (fallback, `cs_march` in `shader.wgsl`, `RtBlur::march`): `src/rt_shadow.rs` builds a window of solid/air bits per cube face (whole faces up to `WINDOW_SIZE` = 256 columns per face, otherwise windows on the faces turned toward the player) plus 8×8-column max-height tiles, rebuilt in `Renderer::update_rt_window` when the player moves far, changes face, or a block is edited (`rt_dirty`). `rt_shadow()` walks those cells toward the sun: 3D DDA in block space on short segments (re-linearised for the planet's curvature), bisection across cube-face edges, and adaptive steps that double (up to `RT_MAX_STRIDE`) while a climbing ray passes above the max-height tiles.
- `RtParams`/`FaceWindow` in `rt_shadow.rs` must match the WGSL structs. The UI bind group uses `rt.enabled = 0` ("lit, don't read the shadow texture"); in hardware mode `update_rt_window` still writes `enabled = 1`.
- The debug overlay's GPU timer (`src/gpu_timer.rs`) shows geometry, rays (downsample + shadow compute), blur, lighting and text.

### Coordinates (`src/gen.rs`, `CoordSystem`)
A `BlockId` is `{face: 0..6, layer, u, v}` on a cube-sphere. `resolution` is the voxel count per face edge. Cube→sphere uses the Nowell mapping (`cube_to_sphere`), and `cubize_point` is its inverse. Layers are radially **exponential**, not linear: `get_layer_radius(layer, res) = (res/2) * exp(K*(layer/(res/2) - 1))` with `K = 0.85`, so voxels keep a roughly cubic shape at every depth. Convert between world positions and blocks only through `CoordSystem` (`pos_to_id`, `get_local_coords`, `get_block_center`, `get_vertex_pos`). Never hand-roll the math.

### Renderer owns streaming and LOD (`src/renderer.rs`)
`Renderer` is the largest module. Besides the frame passes (deferred geometry/lighting, shadows, overlays, glyphon text), it also owns world streaming:
- `update_view` walks a quadtree per face (`process_quadtree`, logical size `res.next_power_of_two()`). Nodes split on distance against `node_radius * lod_factor`, and `lod_factor` grows as node size shrinks. Leaf nodes at `CHUNK_SIZE` near the player become full voxel chunks (`ChunkKey` → `chunks`). Coarser nodes become heightfield LOD meshes (`LodKey` → `lod_chunks`).
- Mesh generation runs on `std::thread::spawn` workers that get a **cloned `PlanetData`** and send `(key, verts, indices)` back over `mpsc` channels (`mesh_tx/rx`, `lod_tx/rx`). Per-frame budgets cap spawns and GPU uploads. `pending_*` sets dedupe in-flight work.
- A mesh that is no longer required (voxel chunk or LOD node) is kept alive until every required mesh overlapping its area has loaded (the `uncovered` check in `update_view`), so LOD splits, merges and voxel ↔ LOD hand-overs never leave holes. Removed meshes go to `LodAnimator` (`src/lod_animation.rs`) to fade out, and new ones fade in.
- After a block edit, `refresh_neighbors` must be called so the affected chunks get remeshed. After swapping in another planet, call `force_reload_all`: it bumps `Renderer::generation`, and worker results tagged with an older generation are dropped. Without that, a mesh of the previous resolution that was still in flight got stored under a current key and was never rebuilt (a chunk-sized hole into the planet after `]`/`[`).

`MeshGen` (`src/gen.rs`) builds voxel chunk meshes (with AO and skirts), LOD meshes, and debug geometry (player cylinder, crosshair, collision boxes). `Vertex` is `bytemuck::Pod` and uploads directly. All shading (ray-marched sun shadows, atmosphere/clouds, exp² fog, ACES, dithered transparency) is in `src/shader.wgsl`, loaded with `include_str!`. CPU-side uniform structs (`GlobalUniform`, `LocalUniform`) must match its layout.

### Gameplay loop (`src/main.rs`)
`App` implements winit's `ApplicationHandler`; the window and `Game` (renderer, controller, player, planet, console) are created in `resumed`. `Game::tick` runs before every window/device event and on `about_to_wait`: `controller.update_player` (physics), raycast to cursor, `renderer.update_cursor`, `renderer.update_view`; then the event is dispatched. On macOS the surface is tagged Display P3 and `fs_main` converts its output from sRGB to P3 primaries (flag in `sun_dir.w`), otherwise colours show oversaturated. `Physics` (`src/physics.rs`) is a custom kinematic solver. Up is `normalize(position)`, orientation uses `Quat::from_rotation_arc`, and collision samples `exists()` with a 5% edge "shave" margin. `Console` (`src/cmd.rs`) captures keyboard input while open. Water: `PlanetData::water_depth` gives the feet's depth below the sea surface (None outside ocean columns); deeper than `SWIM_DEPTH` (and not flying) `Player::update` hands over to `Player::swim` (`src/entity.rs`): half speed along the look direction, buoyancy toward `FLOAT_DEPTH`, drag, Space = up / surface hop, Left Shift = dive. Fly mode (`flying`) has no collision (`Physics::solve_movement` just integrates position), so `Player::update` enforces its own terrain-following floor: hover clearance above the highest terrain sampled ahead along the current horizontal velocity (`fly_terrain_floor`), only ever pushing the player up (`fly_floor_climb`, rate-limited) and clamping an active descent so it can't cross the floor within one tick (`fly_max_descent`) — so Left Shift (fly down) or diving via pitch can't be used to fly through the ground, and flying on over lower terrain keeps the current altitude instead of hugging the ground. Space/Left Shift climb/descend along the planet-relative up vector in fly mode, independent of where the camera looks. F (first person, planet mode; `main.rs`, decision in `landing::f_action`) lands while flying — an automatic descent along local down (`landing_descent_speed`: fast high up, easing in near the ground; WASD still steers; F again cancels) that switches to walking, or swimming in water, on touchdown (`Player::update` returns true, `Controller::update_player` turns fly mode off) — and is refused over lava (`landing::over_damaging_liquid`); while walking or swimming it takes off (fly mode plus a `TAKEOFF_LIFT` nudge). Its messages go to the HUD's timed status line (`Renderer::show_status`, `STATUS_SECONDS`), since the console is only drawn while open. Liftoff hands galaxy flight the player's velocity (`landing::liftoff_flight`), so a climb doesn't stall at the handover.

Known quirk (don't "fix" it silently, mention it): `src/lighting.rs` is not declared as a module, so it is dead code that isn't compiled. `update_player` runs exactly once per tick; movement and turning speeds are per second (Q/E turn at `TURN_SPEED` in `controller.rs`).

## Runtime controls (useful for manual verification)
- WASD / Space / Left Shift / Left Ctrl (sprint); mouse look (first person); `Q`/`E` turn left/right in both views. In water, Space swims up (or hops out at the surface) and Left Shift dives. In fly mode, Space/Left Shift climb/descend (descending is held back by the terrain floor, see Gameplay loop). LMB mines, RMB places; `1`–`5` or a middle click on a block (picks its type) choose the placed block type.
- `K` toggles first/third person. `F` (first person): take off when walking/swimming, land when flying (refused over lava).
- `F2` saves a screenshot to `screenshots/voxanet_<unix_ms>.png` (creates the folder if needed). `F2` and `Escape` (free/recapture the mouse in first person) are **global keys**: handled at the top of `Game::window_event` before the console's input interception, so they work in planet and galaxy mode and even with the console open. Clicking recaptures a freed mouse in both modes. Entering galaxy mode (liftoff, `/galaxy goto`) closes the console, since it isn't drawn in galaxy mode and an open console swallows all other keys (WASD included).
- The key left of 1 (`` ` `` on US, `^` on German layouts — bound by physical position, `KeyCode::Backquote`) opens the console (a quarter of the screen; ↑/↓ recall earlier commands): `help`, `/debug_mode set true`, `/move_speed get|set <v>`, `/jump_force get|set <v>`, `/hw_shadows set true|false`, `/view set first|third`, `/galaxy home|goto <n> <radii>|add <type> <radius>`, `/screenshot <path>` (same dependency-free PNG encoder in `src/screenshot.rs`, F2's handler and the console command both call `Renderer::request_screenshot`; needs the swapchain's `COPY_SRC` usage, added in `Renderer::new`).
- `--biome earthlike|volcanic|ice` (command-line flag) picks the start planet's type: the game starts on the first galaxy planet of that type (default: #1, Earth-like).
- The player's health is always shown as `HP: x/x` next to the FPS/Block overlay (not gated on debug mode; health drains in damaging liquids like lava on Volcanic planets, regenerates otherwise).
- When debug mode is on: `P` wireframe, `O` collision boxes, `'` freezes frustum culling. The overlay also shows GPU time per part (`src/gpu_timer.rs`, timestamp queries). Apple GPUs overlap passes, so each part is measured from the previous part's end to its own end; use this overlay rather than FPS when profiling.
- For scripted/headless testing (e.g. no keyboard injection available): `Game::tick` (`src/main.rs`) polls two sentinel files every tick and deletes them after acting — `/tmp/voxanet_screenshot.trigger` (contents = PNG path) and `/tmp/voxanet_cmd.trigger` (contents = any console command, run through `Console::exec`).
